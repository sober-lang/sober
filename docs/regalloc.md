# x86 レジスタ割り当て（src/compiler/lower/x86.sober）

src/compiler/lower/x86.sober の正規バックエンドが使う、線形スキャンから優先度順の貪欲彩色へ拡張した割り当て器の設計を 1 つにまとめる。
実装はコード comments に散り、設計判断は開発記録に散っていた。この文書はそれらの要約と裁定の記録で、
コードと報告が食い違う箇所はコードを正とし、その旨を明記する。

対象ファイルは src/compiler/lower/x86.sober のほぼ全体（命令選択・CFG・生存解析・割り当てが 1 ファイルに同居 — B-1d の写し。src/stage1/ir_x86*.zig・
ir_live.zig・ir_cfg.zig が凍結した前身）。正しさの根拠は stage1 が同じ IR テキストから建てた ELF とのバイト一致（scripts/elfeq.sh）で、
中間成分（区間・置き場）そのものの Zig との照合は無い（docs/ir.md 9.5 節）。

## 0. 2 つのバックエンドの使い分け

- `--backend=copy`（st.xcopy = true・e.opt = false）: 素朴な線形スキャン（1 本の連続区間・追い出しは「end が最も遠い区間を落とす」・ヒントなし）。
  凍結した Zig の割り当て器と1 バイトも違わない出力を出す（elfeq・stages の cross がこれを見る）。性能投資の前（性能投資 M4）の写し
- 既定（e.opt = true）: この文書が扱う最適化のバックエンド。区間分割・重み・優先度順の彩色・ヒント・二段方式が全部ここに乗る
- 両者は同じデータ構造（xF）・同じ命令選択・同じ命令符号化を共有し、割り当てのアルゴリズムだけが分岐する（xAllocRegs 内の `if e.opt { ... } else { ... }`）

## 1. パイプライン概観（xFunc — src/compiler/lower/x86.sober）

関数ごとに 1 回、次の順で走る:

```
xFoldScan（opt のみ — gep の番地の融合）
xOrder       // 到達するブロックを逆後順に並べ、opt なら冷たい領域を末尾の 1 区画へ寄せる・ループの範囲 lpR を記録
xLive        // 値ごとの生存区間（線形の外包）+ 重み（wt/wc/hu）+ 冷たい領域の末尾の触れ（tS/tE）
xPieces      // 部分区間の表（S1b）を恒等で作る + 末尾の外包があれば 2 本目の部分区間 + 運搬値の穴（xHolePieces）
xHints       // opt のみ — 兄弟・辺・演算のヒント表
xFloatClass  // opt のみ — xmm に割り当てる値の集合
xAllocRegs   // 一段目: 区間を並べ替え、opt なら xPrioAlloc（優先度順の貪欲彩色）・でなければ素朴な線形スキャン
[xSplitLoops → xPrioRealloc → xUnsplitSpilled]  // opt かつ spill が出たときだけ: 二段目（差分の再割り当て）
xAllocFrame  // 退避域・spill 先の変位・区間を持たない値の番地（1 回だけ）
[命令符号化・終端の配置・線の跨ぎの詰め物]
```

割らない関数は一段目の結果がそのまま最終で、二段目の仕事は「圧のあるループを素通りする値がある関数」だけに閉じる。

## 2. レジスタ集合と呼び出し規約

- 呼び出し規約は自前（ABI は揃えない — オラクルは観測等価であってバイナリ一致ではない。docs/ir.md 6 節）: 引数は全部スタック
  （呼び手が後ろから push、callee は `[rbp + 16 + 8k]`、call の後に呼び手が `add rsp, 8n`）・戻り値は rax
- 割り当て可能な GPR は 10 本、すべて callee-saved: `rbx, r12, r13, r14, r15, rsi, rdi, r8, r9, r10`（xAllocReg — 割り当てる順。
  syscall の引数に使う rsi/rdi/r8〜r10 は後ろへ置く）
- 一時レジスタは rax / rcx / rdx / r11 の 4 本で、割り当てには使わない（xDivRem・xParallelMove の環の解消・符号拡張などが使う）
- xmm は 8 本（xX0+8〜15）が既定。関数が scanb（UTF-8 検査の SSE2 命令）を含まなければ xmm2〜7 も割り当てに使える 14 本（xNXmmWide）。
  scanb は xmm0〜7 を作業に使うため、含む関数はこれらを呼び手の値のために壊さない（xHasScanB・xAllocFrame）
- フレーム = push rbp; mov rbp, rsp; sub rsp, F。`[rbp - …]` に IR スロット（入口で rep stosq ゼロ初期化 — 最適化のバックエンドは 0 を観測できる語〔同じブロックで先に書かれない語の load・番地が逃げる点で書き済みでない語〕を覆う最小の区間だけ〔zeroinit.sober — rep stosq 便 段 1 2026-10-11〕。区間が 16 語以下なら rep stosq でなく xor eax + mov [rbp - …], rax の列〔段 2 — xZeroStores。コンパイラ自身の自己 build の cycles −1.8%。棄てた案: pxor xmm0 + movdqu の列・T = 32 — report-495〕。写しのバックエンドは全語のまま〔elfeq〕。棄てた案: 全語を外す — 毒の実験〔report-488〕で零は観測されなかったが、IR の約束を破る形を判定なしで置かない）→ 退避域 → spill の順
  - 零初期化の沈め（置き場の往復レーン 段 4b (b1-z) — xZeroSink / xZeroSinkCalc・最適化のバックエンドで区間 16 語以下）: 入口から、区間に重なるスロットの番地（slotaddr）を
    持たないブロックだけを辿った領域 E に ret（早期 return）があれば、零初期化を入口でなく E の出口の先のブロック（前線）の頭で吐く。E の中では区間の語を指す
    番地が作られない（定義が使用を支配するので定義のブロックだけ見ればよい）ので、呼び出しを含んでも区間の語は読まれも書かれもしない。条件: E の外から E へ
    戻る辺が無い・前線の前任が全部 E・前線は 4 つまで（どの道でも前線をちょうど 1 回通る）。前線は空の中継として飛ばさない（xFwdTo）。毒の口は入口に残す。
    routing の match（早期 return 66,102 / 83,631 回）で命令 −1.67%。網の限界: 零の位置の誤り（前線で吐かない変異）は毒の口つきでも母集団で観測されない
    （report-488 の「零は観測されていない」と同じ — 要零の判定が保守的）。判定は単体テスト（zeroinit_test の TestZeroSink）で直に見る
  - スロットの彩色（F-1 段 2 — slotcolor.sober xSlotColor・最適化のバックエンドだけ・report-1003）: 要零が空（zeroinit — 入口の 0 を観測する読みが無い）で番地が逃げないスロットどうしが、生存が重ならなければフレームの同じ語を使う。番地の使い道の分類は zeroinit の写し（load / store の定数の変位・定数の gep・call の実引数のうち sret の受け皿〔全語の書き〕・mut 仮引数〔F_MUTP — 呼び出しの間だけ読み書き〕・rt の写しと relocate〔読み書き〕）で、それ以外は逃げ。生存 = スロット単位の後ろ向きのデータフロー（全語の書き = sret の受け皿と、読みを挟まずに全語を覆う store の列の最初の store — そこで死ぬ）。干渉 = 書きの点で生きている別のスロット + 入口で生きているスロットどうし。彩色 = 大きさの降順の first-fit（決定的）。要零のスロットと逃げるスロットはフレームの頭に宣言の順で固めて置く — 入口の零初期化の区間がその中に収まる（serveTlsConn 32624 → 1376 B）。門 = 彩色の候補が 128 語（1 KB）未満の関数は並びを変えない（解析の仕事は関数の命令に比例する — 門なしは自己 build +0.45 G・64 語は +0.12 G・128 語は +0.06 G）。網: 変異「戻りの辺の生存を落とす」は optdiff・「mut の実引数を全語の書きに数える」は stages（自己 build の stage3 が panic）が鳴らす。棄てた案: 要零のスロットも共有して生存の始まりで零にする（零初期化の沈めの器が要る — 段 3 の席）
  - フレームの内訳の計器（F-1 段 0 — report-1003）: 開発の口 `sober build --frame-stat`（1 本の経路）が関数ごとに `frame <関数> <フレーム B> <スロット B> <零初期化 B> <退避 B> <spill ほか B> <spill の部分区間の数>` を stdout へ（xFrameStat）。scripts/framestat.sh（gate framestat）が scripts/framestat.list の上限〔実測 × 1.01〕と照合する — フレームの大きさは出力を変えないので optdiff では鳴らない
- 命令選択はオペランドを全部読んでから結果を書く（割り当て器が「同じ位置で終わる区間のレジスタを始まる区間へ渡してよい」前提を置くための規約）

## 3. 位置づけ（吐く順の通し番号）

- xOrder が到達するブロックを逆後順（post-order の逆）に並べ、吐く順に通しの位置番号を振る: ブロックの頭 = bpos（偶数）、
  命令 k 番目 = `bpos + 2*(k+1)`（偶数）。割る点（境界）は奇数の位置（「次のブロックの頭 − 1」）に取り、問い合わせの位置（命令・ブロックの頭）は
  すべて偶数なので境界で迷わない（xSplitLoops・xHolePieces の割る点の規約）
- opt のときは xOrder が追加で 2 つの並べ替えをする:
  1. 冷たい領域を末尾の 1 区画へ寄せる（3.1 節）
  2. ループの深さ（xLoopDepth）とループの範囲（lpR）を、並べ替え前の逆後順で計算してから新しい位置へ写す
     （並べ替え後だと末尾から本体へ戻る合流の辺が偽の「後ろの辺」になり、ループの深さの帰属を誤る）

### 3.1 冷たい領域の検出と末尾配置（S3a/S3b — xColdBlocks・xColdChain・xColdMark）

- 種 = (a) exit で終わるブロック（panic の点）(b) 遅い道の rt（`rt.slice_grow` / `slice_grow8` / `grow_try` / `map_grow` /
  `region_relocate` / `region_relocate8` — xSlowRt）を呼ぶブロック。`rt.region_alloc` は確保の本道でもあるので種にしない
- 冷たい辺 = 条件分岐の片側だけが、単一入口・単一出口の鎖（`br` だけを辿る — 終端が condbr ならそこで鎖が切れる）を通って種に届くとき、その側
- 広がり方: 冷たい辺の行き先から前向きに「前任（後ろの辺を除く）が全部冷たい」で広げる
- 種をユーザーの呼び出し（再帰など）に取らないのは、熱い呼び出しを冷たいと誤読しないため
- 末尾へ寄せるのは「ループの外（深さ 0）か exit で終わるもの」だけ（逸脱 — 設計は「冷たい領域は全部寄せる」だったが、ループの中の冷たい領域を
  寄せると合流ブロックの仮引数の合体が崩れる実害が出たため末尾配置を見送った。重みの補正（3.2 節）にはループの中の冷たい印もそのまま使う）
  - 棄てた案: 冷たい領域を全部（ループの中も）末尾へ寄せる — revcomp で合流ブロックの仮引数のレジスタが熱い道の実引数と逆に入れ替わり、
    1 文字ごとの後ろの辺に 3 命令の入れ替えが発生（命令 +3.3%・cycles +13%）。
  - 棄てた案: 冷たいブロックの判定をブロック単体（遅い道の rt を呼ぶブロックだけ）にする — 冷たい道の中の速い道（先端での append の
    インライン）の使用が深さの重みのまま残り、1BRC の main で挿入の道でだけ働く値が重み 129 のまま熱い部分のレジスタを占めた
  - 棄てた案: Ball–Larus 型の静的分岐予測（「呼び出しへ進む側は起きにくい」）— ユーザーの呼び出しを種にし、再帰・熱い呼び出しを冷たいと誤る
   
- 末尾の触れは本体と別の外包（xTouch の `tS`/`tE` — 4.3 節）: 1 本の連続区間のまま末尾へ寄せると外包が関数の終わりまで伸び、
  熱い値と全部重なった（fannkuch 23.2 → 56.5 G）
- 本体 ⇄ 末尾の境界の写しは辺ごと（xSplitMoves — 6 節）。割る点は「末尾の始まり − 1」の 1 か所（e.cuts に足す）

## 4. 生存区間

### 4.1 線形の外包（xLive・xTouch）

- Zig 版の写しの規律から唯一逸脱した部分（docs/ir.md 9.5 節）: ブロック数 × 値の数のビット集合で不動点を反復する代わりに、上向きに露出した
  使用から前任へ辿る経路探索（SSA の path exploration）。到達するブロックの live-in/live-out は最小不動点と一致するので区間は同じ —
  バイト一致（elfeq）がそれを示す。メモリは使用の総数に比例し、stage1 の巨大関数の爆発（src/compiler/app が 589 s / 29 GB）を構造的に持たない
- 値ごとに 1 本の線形の外包 `[ivS, ivE]`（最初の触れ〜最後の触れ。live-in のブロックの頭・live-out の前任の終わりも触れる）。
  穴は無い（兄弟の枝の片方でだけ生きる値も、吐く順でもう片方を跨げば両方で「生きている」扱いになる — 構造の要点 4）
- 冷たい末尾の区画（3.1 節）に入ってからの触れだけは別の外包 `tS`/`tE`
- remat（imm32 定数・スロットの番地 — 10.1 節）は区間を持たない（`xTouch` が早期リターン）

### 4.2 部分区間の表現（S1b — 区間分割レーン）

値ごとに 1 本だった区間を「部分区間」へ拡張する際の設計判断:

- 区間の番号空間を値の番号と共有する: 値 v の最初の部分区間の番号は v 自身、続きは `pnx` の鎖（番号 `nv` 以降・開始の昇順）。`pv` = 部分区間 → 値、
  `npc` = 部分区間の総数。部分区間が 1 本の値は `pnx[v] = -1` で、今までの「値ごとに 1 本」と出力が完全に同じ
  - 棄てた案: 値ごとの部分区間の別表（CSR の `[開始, 終わり, 置き場]`）— 割り当て器の全読み口を別表へ書き換える面積に対し、番号の共有なら
    `ivS`/`ivE`/`loc`/`xPrioAlloc` がそのまま部分区間を扱え、「1 本の間は出力不変」が自明になる
- 割り当ての単位は部分区間（`xAlloc`/`xPrioAlloc`/`xPrioFits`/`xSyscall` の生存の走査は全部部分区間の番号で回る）。値の性質
  （重み・float クラス・ヒント）は `pv` 経由で値へ写して読む
- spill 先は値ごとに 1 つ（`spd` — 同じ値の部分区間で共有。最初に spill された部分区間の順に変位を配る）
- 置き場の読みは位置つき `xLocAt(e, v, p)`（部分区間の鎖を開始の順に辿り「終わり ≥ p」の最初を取る。区間が 1 本なら `e.loc[v]` の速い道）:
  命令の被演算子・結果は `e.pos`、終端と辺の読み元はブロックの終わり、辺の書き先は行き先のブロックの頭、入口引数の読みは入口の頭

### 4.3 部分区間を作る 3 つの経路

`xPieces` は恒等（値ごとに 1 本）を作るだけで、割るのは次の 3 箇所:

1. 末尾の区画の外包（3.1 節 — 本体の触れが無ければそのまま 1 本、あれば 2 本目の部分区間。重み 1）
2. 運搬値の穴（T2 — xHolePieces・下記 4.4 節）
3. 二段目のループ境界分割（S2 — xSplitLoops・5 節）

### 4.4 運搬値の穴（T2 — xHolePieces）

- 動機: ループの頭の仮引数（運搬値）がループの後ろでしか使われない場合、線形の外包がラッチまで伸びて戻り辺の実引数と重なり、
  同じレジスタを取れず戻り辺に写しが残った（葉の `mov r14, rbx`）
- 形: 本体の区間を、生きているブロック（live-in・頭）の吐く順の連なりごとの部分区間に割る（間は穴 — 値はそこで死んでいる）。
  連なりの終わりは、出ていく辺の先で生きていればブロックの終わり、でなければブロックの中の最後の使用（xHoleEnd）。部分区間の重みは値の重みのまま
  （どの連なりも同じ）。穴をまたぐ辺の写しは既存の xSplitMoves がそのまま出す
  - 注記（第 1 便 (d) ① の試行）: この「値の重みのまま」は、部分区間の数だけ重みを重ねて持つ水増しに見えるが、今の貪欲彩色の下では
    境目の結合の代わりとして働いている（中に使用の無い運搬値の部分区間がレジスタに居続け、境目の写しが熱いループに出ない）。部分区間ごとの中の重み
    （L1 の C* と同じ規則）に直すと fannkuch +2.0%・mandelbrot +1.0%・1brc +1.5%（命令）で退行し、境目の費用の判定（13 節 4）を足しても戻らなかった。
    （差分は開発記録に保存 — L2 型の選び方を作るときの部品）
- 連なりの切り方（区間の便 段 1 R1 — report-528）: 吐く順で続くブロックの列でも、値がブロックから出ていかない（終わりがブロックの終わりより前 —
  ラッチの手前で死ぬ運搬値）ところで切る。運搬値の部分区間が更新値の定義の前で終わり、更新値（戻り辺の実引数）が仮引数と同じレジスタを取れる
  （logagg main の `lea r8,[rbx+1]; mov rbx,r8` — 72.9 万回）。連なりの終わりの数えと割りは 1 回の走査（判定の仕事を半分に）
  - 単独では 2 題材が退行した（report-522 2.2 — シーソー）。対策 2 つと組で入れた: 予約（8 節 — mandelbrot の戻り辺の環）・穴の部分区間の
    ループ境界分割（5.1 節 — revcomp の内側ループの枠の占有）
- 効果: 葉の熱いループが 12 → 8 命令（写しの鎖が全部消え、運搬値どうしが同じレジスタに合体 — 可換の入れ替えも不要になった）。
  cycles（layvar 8 配置中央）: fasta −12.7%・revcomp −11.5%・knucleotide −5.1%・1brc −3.6%
- 副作用で踏んだ潜在バグ: xSplitLoops の割る点の併合が、重複を除いた結果を前の列の先頭へ書き戻すだけで末尾を切り詰めておらず、
  値をまたいで重複する割る点があると昇順が崩れて xSplitMoves の二分探索が割る点を見落とし、辺の写しが抜けた（自己ビルドしたコンパイラが
  `parser.parametersN` を誤コンパイルして実発）。修理 = 併合結果を新しい列として作り直す
- 値札: gran（葉）題材の予測ミスが 0.55 M → 4.5 M に増える（検査点の間引きの数え口が、ループが短く速くなったことで予測を外すようになった —
  割り当ての問題ではなく間引きの数え口側の問題。別便へ申し送り）

## 5. 二段方式によるループ境界分割（S2 — xSplitLoops・xPrioRealloc・xUnsplitSpilled）

### 5.1 動機と最終形

一段目（割らない）の結果で spill が出たとき、圧のあるループを素通りする値だけを境界で割って二段目を回す（二段方式・
で着地）。

- 圧のあるループ = 一段目で spill した値の定義・使用がループの範囲（吐く順の `[頭, 体の最後]`）の中にあるループ。組（int/xmm）ごとに
  spill した値の数を数える
- 素通りの値 = 外包が範囲を丸ごと含み、範囲の中に定義も使用も無い値。候補は値の 1 本目の部分区間と、運搬値の穴（4.4 節）で割れた値の本体の
  部分区間（区間の便 段 1 R1 — 穴の 2 本目以降が内側のループを素通りすると、値の 1 本目しか見ない形ではその部分区間が割れず、値の重みのまま
  内側のループのレジスタを塞いで熱い一時値 2 本を spill に落とした: revcomp の外側の運搬値 — report-528）。範囲の手前と後ろ（奇数の位置）で割る。真ん中の部分区間は重み 0
  （最後に割り当てる — ループの中だけ spill するか兄弟のヒントで同じレジスタを得る）
- 本数の上限: ループ・組ごとに「一段目で spill した値の数」まで。素通りの値を優先度の低い順（一段目で先にどかされる側）に先着で枠を取る
- 入れ子は、値の使用の間の隙間ごとに、隙間に丸ごと入る最も外の圧のあるループで割る
- 二段目は差分の割り当て（xPrioRealloc）: 一段目のレジスタごとの列（`aL`/`aB`/`aC`/`aN`）をそのまま持ち越し、割った値の外側の部分区間を
  一段目のレジスタに固定（`pfix` ≥ 0）して足し、残り（真ん中・一段目で spill した値の中の部分区間）だけを優先度順に割り当て直す
- 割らない関数は一段目の結果がそのまま最終 = 今までと 1 バイトも変わらない

### 5.2 棄てた形

- ループの中で使う値も割る（内側ループの出入りごとにレジスタ間の写し）: fannkuch の命令 23.2 → 32.9 G で棄却
- 素通りの値を圧と無関係に全部割る: ループの中の値が素通りの値のレジスタを先に取り、得るもの無しの写しが出入りごとに発生
  （fannkuch +16%・knucleotide +8%）。真ん中の重みを 0 にしても「そのレジスタがループの中で空いているとき」しか兄弟ヒントが効かず、
  ループの中の値に番号順の最初のレジスタを先取りされる
- 二段目で全部を割り当て直す（固定を置かない）: 割った値の外側の部分区間は重みが分かれて優先度が下がり、一段目でレジスタだった値が
  熱いループごと spill した（knucleotide の rt.map_find で spill 14 → 23・cycles +5〜8%）→ 一段目の固定（pfix）を導入
- 割る候補に spill 済みの値も含める: 優先度の低い順に選ぶと一段目ですでに spill していた素通りの値が枠を先に取るが、
  レジスタを持っていないので割っても何も明け渡さない（fannkuch の main で命令 +1.0%）→ 候補は一段目でレジスタを持っていた値だけに限定
- 真ん中・spill した値の中の部分区間を重みどおりに優先度へ混ぜる: revcomp の cycles +10.6%（熱い一時値を押し出し、運搬値が
  毎反復 store → load の鎖になった）→ 一段目で spill した残りの後に余りの枠だけを取る（「形 2」）形へ修正

### 5.3 T1（spill した値自身の分割）

区間分割レーンの素通り限定（5.1 節）では拾えない、spill した値そのものの分割:

- 候補: 一段目で丸ごと spill した値（末尾の区画の部分区間を持たない）のうち、区間がどれかのループと重なるもの
- 割る場所: 使用ごとに最も内側のループを取り、そのうち入れ子にほかの選ばれたループを持たないものの境界で割る。条件は
  「値の区間がループの外へはみ出す」と「一段目の割り当てで、どれかのレジスタがループの範囲で空いている（楽観）」の両方
- 外側の部分区間は spill に固定（`pfix = -2`）。内側の部分区間（`pfix = -3`）と割った値の真ん中は、一段目で spill した残りの
  後に余りの枠だけを取る（5.2 節の教訓の再適用）
- 二段目の後、全部 spill のままの値は 1 本に畳み戻す（xUnsplitSpilled — spill 先は値ごとに 1 つなので写しは不要。残すと鎖をなめ続け、
  自己ビルドの仕事が +0.5% 増えた）
- 条件分岐の写しが要る側がループの出口（深さが下がる辺）なら、その写しを関数の末尾へ出す（辺の外置き — 熱いループの本体に出口の写しを
  残さない）。棄てた案: 外置きを辺の向きで絞らない — revcomp の熱いラッチまで末尾へ出て毎反復 jmp が 2 本になった
- 効果: gran（葉）の命令 −13.9%。pwt の自己ビルド仕事は +0.43%（ラチェットの値札つきで受容）

### 5.4 区間分割レーンの決算

- 1BRC の冷たい道の値札（+4%）は S3a で回収。冷たいブロックの末尾配置の壊滅（A の的）は S3b の 2 本の外包で解消
- 「展開を増やすと割り当てが劣化する」という仮説は成り立たなかった: 展開を増やすとコンパイラ自身の命令数はむしろ 2〜4% 減り、
  自己ビルドの悪化は全部「展開で増えた IR を処理するコンパイル時の仕事」だった。割り当ての問題ではなくインライナの予算の問題
- fannkuch の Go 比 1.02× への端数は、S2・S3・T1・T2 のどれでも動いていない（熱いループの割り当ては変わるが命令数は同じ — 検査点の分岐予測や
  ループの形の問題で、割り当て器の守備範囲の外）

## 6. 重み（xWeigh・xWeighArgs・xColdBlocks）

- 値の重み `wt` は、定義・使用の出現ごとに `8^depth`（深さ 4 で頭打ち = 4096。xWeigh の `w` テーブル）を加算する
- 辺の実引数は、行き先の仮引数がその値自身（恒等実引数 — 後ろの辺で変わらない変数）なら重みに数えない（置き場が同じなら写しは 0 命令 —
  S3a・xWeighArgs）
- 冷たい補正（S3a）: 「ループの中の熱いブロックに使用が無い値」（`hu = 0` — 定義・恒等実引数・ループ外の使用は `hu` に数えない）だけ、
  重みを `wt` から「冷たいブロックを深さ 0 で数えた `wc`」に置き換える
  - 棄てた案: 冷たいブロックの重みを全部の値で深さ 0 にする — 熱い道と遅い道の両方で使う値の重みが下がり、長い区間が短い熱い一時値を
    追い越して revcomp の内側ループで spill が増えた（cycles +18.3%）。hu=0 の値だけに絞ることで回避
  - 棄てた案: 優先度を密度（重み ÷ 長さ）にする — 全題材で +5〜20% の退行で棄却
- 動機となった実例: 1BRC の main で、冷たい道（map への新規挿入）でしか働かないループの頭の仮引数が、冷たい使用も
  深さの重みのまま数えられて重み 129 に達し、熱い部分のレジスタを 1 本占有していた。重みの補正後は約 22 まで下がり、熱い一時値
  （重み 16〜24）に負けて spill される側に回った
- `xSpillCost`（= 重み ÷ 区間長。長さは 256 で頭打ち）は写しのバックエンド（線形スキャン）の追い出し判定だけに使う。opt の優先度順
  彩色（xPrioAlloc）は使わない（6.5 節既知の弱点も参照）
  - 頭打ちが無いと、関数の端から端まで生きループの中で使われる値（slice の len/base）が長さで割ると安く見え spill された
    （fannkuch の内側ループ — M6 で発見）。64/1024 も試したが結果は同じ

## 7. 優先度順の貪欲彩色（M8 — xPrioAlloc・xPrioSort・xPrioPick・xPrioFits）

- 順序: 重み `pwt`（部分区間の重み）の降順、同点は区間の長い順、さらに同点は値の番号の小さい順（決定的 — xPrioSort）
- 彩色: 優先度順に 1 本ずつ、重ならないレジスタへ（ヒントのレジスタを先に試す — xHintReg）。置けなければ spill
  - 棄てた案（写しのバックエンドの素朴な線形スキャン）: 「その時点の active 集合の中で最安を落とす」局所的な選び方 — 内側のループで重く使う
    長命の値（slice の base）を短い一時値より先に落としていた
- 重なりの判定: `s < e'` かつ `s' < e`（end ≤ start は共有可 — 同じ点で終わる区間と始まる区間は重ならない）
- O(log n) 化（S1a）: レジスタごとの割り当て済み区間を開始の昇順の列に持つ（割り当て済み区間どうしは重ならず開始も違うので
  「終わり ≤ 次の開始」。重なりうるのは「開始 ≤ s の最後」と「開始 > s の最初」の 2 つだけ）。枠は平らな配列（満杯なら倍の枠を取り直す —
  区間の数 × 32 を関数ごとにゼロ埋めすると自己ビルド +0.6 G だったため）
- 追い出し（区間の便 段 2 D2 — xPrioEvict）: 置けない部分区間 v は、各レジスタで重なる先客の費用の和が v の費用の半分以下なら先客を列から外して
  v を置き、先客をヒープへ戻して優先度の順に置き直す（別のレジスタが空いていればそこへ・無ければ spill）。1 つの部分区間が追い出されるのは 1 回まで（XEV_N）
  - 追い出せる先客は「運搬値の穴（4.4 節）で割れた値の、中に使用の無い部分区間」だけ（定義と境目の写しだけの素通りの区間）。費用 = 中の触れの重み（定義）+
    隣の部分区間がレジスタ（か未処理）なら境目の写し 1 本（xPcCost）。v の費用は、穴の部分区間なら同じ式・ほかは部分区間の重み
  - 動機: 段 3'（report-524）の後の 1brc main で、lea の結果（区間 2 命令・中の使用 10 万回）が spill に落ち、5 本のレジスタを中に使用が 0 回の素通りの
    部分区間（値の重みを丸ごと持つ — 13 節 2）が塞いでいた（report-525 3 節）。命令: 1brc −1.85%・knucleotide −1.23%・routing −0.09%・jsonapi −0.03%・
    logagg +0.015%（report-526）
  - 棄てた案（report-526）: 中に使用のある先客も追い出す形 — 静的な深さの重みは兄弟の腕（毎周どれか 1 つだけ走る）を全部熱く数えるので、腕に散った使用の
    和と境目 1 本の比較が実回数と逆になり、ヒントで合体していた辺の写しのずれも費用の外（knucleotide +2.8%・logagg +0.9%・jsonapi +0.3%。余裕 2〜3 倍でも
    logagg +0.27〜0.39%）。余裕なし（和 < 費用）— jsonapi の Parse で同じ点で定義される 2 値の僅差の入れ替えが連なり +0.34%。部分区間ごとに覆うブロックだけを
    遅延で走査して中の触れを数える形 — 長い部分区間を何度も舐めて自己 build の判定の仕事 +3.1 G（関数を 1 回走査する形は +0.28 G）。連鎖の上限 N = 2 / 4 —
    12 題材の ELF も判定の仕事も N = 1 と同じ

## 8. ヒント（xHints・xHintEdge・xHintReg・兄弟優先）

優先度順の彩色で「どのレジスタを選ぶか」だけに作用し（彩色の順そのものは変えない）、次の優先順位で空きレジスタを探す（xHintReg）:

1. 同じ値の割り当て済みの部分区間（隣（前後）を先に — 境界の写しを消すのが目的）、無ければほかの兄弟部分区間
2. 値のヒント（`hP`/`hA1`/`hA2`/`hOp` — 辺の実引数 → 行き先の仮引数、仮引数 → 入りの実引数 2 本まで、演算の結果 → 左の被演算子）

組（int/xmm）をまたぐヒントは無視する（`xHintLoc` が `xIsXmm` の一致を見る）。ヒントが無い／空きが無ければ、通常どおり空きレジスタの先頭を取る。

予約（一段目だけ — 区間の便 段 1 R1・report-528）: 辺の実引数をレジスタ r に置いたとき、行き先の仮引数が運搬値（ループの頭の仮引数）でまだ置かれて
いなければ r を予約し、ヒントの無いほかの部分区間は空きの先頭を選ぶとき r を後回しにする（xPrioPick — 仮引数の 1 本目を処理したら解く）。
運搬値の更新値は重く仮引数より先に置かれるので、更新値の側に仮引数のヒントを持たせても効かない（仮引数はまだ置き場が無い）。予約が無いと、穴で縮んだ
別の仮引数が空きの先頭としてそのレジスタを取り、仮引数どうしの置き場が戻り辺で 1 つずつずれて並行コピーが環になる（mandelbrot の xmm の φ 4 本 —
r11 を中継ぎに 5 写し・cycles +58%）。
- 棄てた案: 予約を合流の仮引数（前向きの辺）にも掛ける形 — mandelbrot・revcomp・fannkuch は得だが knucleotide +1.7%・routing +0.5%・1brc +0.4%（命令）
- 判定の仕事: レジスタを舐める形は自己 build +0.24 G — 予約のあるレジスタのビット（free[64]）で畳んで +0.02 G

## 9. 合流の並行コピー（xParallelMove・xEdgeMoves・xSplitMoves）

- 辺の実引数 → 仮引数の写しは並行コピーとして出す（xParallelMove）: 準備の整った写し（書き先を他の生きている写しが読まない）から
  順に処理し、循環がある場合は 1 本を `r11` へ退避してから進める（環の解消）
- opt は辺の写しの位置（コストの数え方）を見ず、「実引数と仮引数が同じ置き場なら写しは 0 命令」として扱う（xEdgeMoves が判定し、
  不要な辺を `xFwdTo` で空の中継として飛ばせる）
- 割れた値（部分区間を持つ値）の辺ごとの写し（xSplitMoves）: 辺の両端（元の終わり・行き先の頭）を覆う部分区間の置き場が違う値だけを足す。
  死んだ値でも、覆う部分区間があれば書き先が外包の中で確保されているので写してよい
  - 例外 = 行き先の仮引数: 行き先の仮引数の列にある値は、辺の仮引数の写し自体がその値を書くので外す（外さないと仮引数の写しと
    二重に書いてしまう — S2 で誤コンパイルを踏んだ実例の一般形。判定は当初「最初の部分区間が行き先の頭で始まる」だったが、S3b で
    「行き先の仮引数の列にあるか」（`xIsParamOf`）に一般化した）
  - 関数の引数の置き場（呼び手が積んだ番地）へ書く写しは省く（入口からずっとその値を持っている）
  - 書き先 = 読み元の写し（実質恒等）は `xParallelMove` が出さないので `xEdgeMoves` の判定からも外す（数えると写しの無い辺で
    条件分岐の向きが反転する）
  - spill 先が既に正しい辺の reg → mem の写し（store）は出さない（第 1 便 (d) ③ — xSlotValid）: SSA の値は変わらないので、spill 先が
    値を持っていれば書き直しは要らない。割れた値ごとに前向きの「すべての道で」の不動点 — 入り(b) = 前任の出の論理積（入口は偽）・出(b) = b の終わりで部分区間に
    覆われ、かつ（spill 先にいる ∨（入り(b) ∧ b ≠ 定義のブロック））。結果は xF.svOk（割れた値 × ブロック）。定義のブロックは外包の始まりのブロックで
    代用できない（吐く順で定義より前のブロックが外包に入る — gates の json_decode で捕捉した潜在バグ）。fannkuch 命令 −0.38%・cycles −0.8%。
    自己 build の値札 +0.32 G（ratchet 60.7 → 61.0）。これで bce④（13 節）の損の主因が消え、bce④ は得に転じた

## 10. spill（1 か所原則 — xAllocFrame・xGet/xGetInto/xPut）

- spill 先は値ごとに 1 つ（4.2 節）。同じ値の複数の部分区間が spill されても、変位は共有する（最初に spill された部分区間の順に配る）
- spill 先の合流（置き場の往復レーン 段 4a — opt・xSpillJoin / xJoinSlots）: 辺の実引数と行き先の仮引数がどちらも spill 先を持ち、区間が
  重ならないなら、同じ変位を配る（1 か所原則は「合流した値の組で 1 か所」）。辺の写しが「同じ置き場」になり、9 節の 0 命令の扱いが効く
  （jsonapi の Parse の戻りの辺の spill 先どうしの写し — mem → mem）。割り当て（どの値がレジスタに載るか）は変えない
  - 干渉は値の全部の部分区間（レジスタに置いたものも — 割れた値の spill 先は xSlotValid の前提でそこでも値を持つ）で見る。部分区間の間の
    穴（運搬値の穴・本体と末尾の区画の間）は値が死んでいるので数えない。外包（最初の始まり〜最後の終わり）で見る初版は、末尾の区画で
    使う値が全部の組を締め出して効きが 1/4 だった（jsonapi −0.7% 対 −3.1%）
  - 重なりの定義はレジスタの共有（xPrioFits）と同じ。辺の写しが仮引数の置き場へ書く点（前任の終わり）は仮引数の区間の外だが、その辺の上で
    値が要る別の値は行き先の入口で生きていて仮引数と重なるので群に入らない（xLive の opt の注と同じ理屈）。群は 16 値まで・深いループの辺から併せる
  - 届かない形: 合流のブロックの仮引数が、ループの頭の仮引数（その写しを受け取る）と、ループを出る道で同時に生きている形（値は同じでも区間が
    重なる）。値の等しさを見る合流（copy coalescing）は入れていない
- spill の枠の彩色（F-1 段 1 — xSpillColor・opt・report-1003）: 合流の後、spill 先を持つ群（合流の群・群でない値は 1 つ）の区間 = 群の全部の値の全部の部分区間（レジスタに置いた分も — xSlotValid の前提）の外包（穴は使わない）で、重ならない群どうしが同じ枠を使う。重なりの規則は xIvMeet / xPrioFits と同じ（レジスタの共有と同じ干渉なので、辺の写しの書き点の論証も合流と同じ）。算法 = 線形走査（始まりの順・同じ位置は群の番号の順 — 安定なマージ・終わりが始まり以下の枠を空きの列へ戻してから配る・v128 は 16 B の別の列）— 決定的。serveTlsConn の spill 21976 → 2816 B・自己 build のフレームの和 1.14 → 0.96 MB。値札 = 自己 build の命令 +0.09 G（計算 — 出来たコードは安くなる側）。写しのバックエンドは今まで通り値ごとに専用（elfeq）。棄てた案: 部分区間の穴まで共有する（xSlotValid の前提を崩す）・位置の桶（関数の位置の数に比例する表 — +0.2 G）
- 定義直後の読み直しの省略（段 4a — opt）: xPut がフレームへ store した直後（表の位置が動いていない）に同じ値を xGet / xGetInto で読むなら、
  store の読み元のレジスタをそのまま使う（xGet は読み元が scratch と同じときだけ）。ブロックの頭で消す（別の前任から入る道ではレジスタに値が無い）
  - レジスタ版（段 A — report-509）: xPut が値をレジスタへ写した直後（`mov rsi, rax`）に同じ値を写しの読み元へ読む xGetInto（`mov rax, rsi` — 戻り値の rax など）は省く
- 吐くときの scratch の中身の覚え書き（段 B の D1 — report-512・opt）: rax / rcx / rdx が今持つ値（SSA の値 — spill 先の変位ではない）を
  xF に覚え、xGet が同じ値をまた同じ scratch へ読むなら読みを省く（routing の Route の 6 語の load ごとの基底 `mov rax, [rbp-…]` の読み直し）
  - 白名簿の形: 覚え書きを引き・書くのは白名簿の命令（定数・load / store・番地を出さない gep / slotaddr — xMemoOp）を吐いている間だけ。名簿の外の
    命令の頭とブロックの頭で全部消し、終端の前で止める。名簿の外の吐き方（xDirectBin の rax 経由・並行コピーの中継・rt の展開ほか）が
    scratch を書くのを 1 つずつ追わない — 漏れが誤コンパイルになる
  - 名簿の中で scratch を書く口は xGet（xMemoHit — 引いたうえで以後 v を持つと記す）と、結果を書いた直後の xPut（xMemoSet）の 2 つだけ。
    rax を結果の書き先に使う道（imm64 の定数・置き場が gpr でない load）はどれも直後に xPut(res, rax) を通る
  - 鍵が値なので、置き場（部分区間）や spill 先の共有（xSpillJoin）に依らない。xGet の「scratch へ書く道」（remat の即値・lea・xmm の movq・
    spill 先の load）は 1 か所で覚え書きと段 4a の E を引く
  - 網: 変異「ブロックの頭で消さない」「呼び出しの頭で消さない」「xPut で更新しない（= 結果の書き先 rax で消さない）」を optdiff --mut が殺す
  - 棄てた案: 名簿の外の吐き方ごとに書いたレジスタを消す形（口が散っていて漏れの危険が大きい — report-508 2.2）。R3（並行コピーの写しで
    書き先がすでに同じビットを持つなら省く）はこの部品に乗らない — 辺の写しは名簿の外で、写しの時点で被演算子のレジスタを知る別の口が要る
    （report-512 / 513 — PINS）
- 吐き方の命令選択（段 A — xDirectBin — 割り当ては変えない）: 定数倍は 3 番地形の `imul d, x, imm`（`mov rcx, imm; imul d, rcx` の即値の読みと d への写しを省く）。
  右の被演算子が結果のレジスタにある可換の演算（add / mul / and / or / xor）は `op d, 左` で（rax 経由の `mov rax, 左; op rax, d; mov d, rax` を省く）。sub は今までどおり rax 経由
- フレームは `[frameTop)` の下に退避域、その下に spill 域。関数の引数（仮引数）が spill された場合は、呼び手が積んだ
  `[rbp+16+8k]` をそのまま spill 先にする（store は不要）
- 区間を持たない値（到達しないブロックでしか定義されない）も番地だけは有効にしておく
- spill した部分区間は、区間内の全使用で load・定義で store する（共有の宛先 1 か所に対する store/load — 二重化はしない）
- 退避対象は「割り当てに使ったレジスタ」に限らない: スロットのゼロ初期化を使う関数は `rdi` を、syscall を含む関数はその引数レジスタ
  （`rdx` を除く）を、scanb を含まない関数で xmm2〜7 も割り当てに使った場合はその分を、それぞれ割り当てとは無関係に退避する

### 10.1 remat（作り直す定数 — M5）

- `e.remat[v] = 1`: 値が `OpConst` の imm32 範囲の定数 → 区間もレジスタ/spill 先も持たず、使う点ごとに即値を作り直す（`xMoveImm`）
- `e.remat[v] = 2`: 値が `OpSlotaddr`（スロットの番地）→ 使う点で `lea rbp + 変位` を作り直す。1.0× アタック便で、番地が spill され
  多値の結果の写しのたびにフレームから番地を読み直していた実例（1BRC の main）への対策
- `xSrcLoc` が並行コピーの読み元として `xRemat + 2*v` の印（偶数・`xSpill` より大きい・どの書き先とも重ならない）を返し、
  `xParallelMove` が種類ごとに `lea`/即値の書き込みへ振り分ける

## 11. float のクラス（xFloatClass）

- float の演算を 1 つも持たない関数は xmm のクラスを立てない（早期リターン）。立てないと int のブロック仮引数の環まで xmm に置かれ、
  使うたび `movq` で汎用レジスタへ往復していた（段 6 P4-6 で発見）
- 候補は「float 2 項演算の結果」「float の `OpConst`（remat でない）」「float の `OpLoad`（folding されていない）」「ブロック仮引数」。
  int の演算・比較・番地計算・分岐条件に使われる値は不動点反復で xmm のクラスから外す（store の値・呼び出し引数・ret は外さない —
  外すと spectral-norm が 2.7 倍遅くなった実例あり）
- この修理の前は、fannkuch の端数の正体が「優先度」ではなく「float クラス判定の穴」だった（ブロック仮引数が int の比較に使われても
  xmm のまま扱われ、長さと添字の比較のたびに `movq` が入っていた）

## 12. 冷たい道・熱い道をまたぐ値の帰属（既知の脆さの背景 — xColdChain の構文依存）

`xColdChain` は「条件分岐の片側から、`br` だけの単一入口・単一出口の鎖を辿って種に届くか」で冷たさを判定する。種に届く前に 1 つでも
条件分岐（`condbr`）があると、そこで鎖が切れて手前は熱いまま扱われる。この判定は構文的（鎖の形）であって意味論的（必ず遅い道を通るか）
ではないため、呼び出しがブロック 1 つ分動くだけで冷たい印が広範囲に消える・現れることがある（14 節参照）。

## 13. 既知の弱点（2026-10 時点）

最適割り当てオラクル（最小費用流による厳密解 L1 との比較）便で名指しされた、現在の設計の限界。どれも「直す」ではなく「現状の記録」として
挙げる — 直す候補はに材料として並んでいるだけで、裁定済みではない。

1. 冷たい領域の判定が構文に依存する（12 節）: `xColdChain` の「`br` だけの単一入口・単一出口の鎖」という条件は、冷たい道の途中に
   分岐が 1 つ入るだけで鎖が切れ、その手前のブロック群が丸ごと熱い扱いに戻る。mapfuse 便（コミット 5678b37f）で、`region_relocate8`
   の呼び出し位置が 1 ブロック動いただけで 13 ブロックの冷たい印が消え、熱いループの一時値 6 本が spill に回った（knuc cycles
   −14.3%・命令 −30.6% の得と引き換えに、1brc が割り当ての非単調で +6.5% 退行）
2. 部分区間の重み = 値の重みのまま（穴・分割のどちらでも）: 運搬値の穴（4.4 節）や二段目の分割（5 節）で作られる部分区間は、
   重みを「その部分区間の中の定義・使用」で数え直さず、値全体の重み（真ん中は例外で 0）を引き継ぐ。冷たい領域が構文判定で見誤られると
   （上記 1）、この重みがそのまま誤って熱い値に波及する。ただし中の重みへ直す形は今の貪欲の下では逆効果（4.4 節の注記・下の 4）
3. 優先度順の貪欲彩色に追い出しが無い（7 節 — 2026-10 の段 2 で「穴の素通りの部分区間」だけは追い出せるようにした。一般の追い出しは静的な重みの下では逆効果）: 一度置いた区間は、後から来たどれだけ重い区間にも明け渡さない。最小費用流オラクル
   （L1）との比較では、1BRC の main で greedy が既に 32.5%（hd 版）、mapfuse 後は 58.2%（mf 版）のギャップを持つ。最適解は長い
   区間（熱いブロックを丸ごと跨ぐが使用の疎な値）を spill にして短い熱い一時値をレジスタに残すが、greedy は重みの降順で先に長い
   区間を置いてしまい、短い一時値を締め出す。冷たい領域の誤判定（弱点 1）は引き金に過ぎず、増幅しているのはこの順序の脆さ
  
4. 合流の継ぎ目の写し（辺の並行コピー）はコスト・優先度のモデルに入っていない: ヒント（8 節）は彩色の「色の選び方」だけに効き、
   割り当ての優先順位（7 節の重み順）自体は写しの本数を見ない。最小費用流オラクル（L1）も同じ理由でこの費用を見ておらず
   greedy と L1 のギャップは「写し込みの増減」を含まない下界にとどまる。
   境目の費用まで入れた L2（窓ごとのブロック単位 reg / mem・定義での store・ラグランジュ緩和 + 値ごとの min-cut + 分枝限定）の証明つき最適との
   差は 1brc の main で −11.8%・fannkuch で −6%（回収の見込み）。第 1 便 (d) で出口の冗長な store は消した（9 節 — ③）が、取るかどうかの判定に境目の費用を
   入れる形（②）は 9 題材で無効果、部分区間ごとの重み（①）は逆効果だった（4.4 節の注記）。教訓: 正直な費用モデルは、選び方が L2 型（境目を挟む部分区間を
   結合して解く）でないと逆効果になる — 貪欲の順序が費用モデルの歪みを前提に釣り合っている
   - 第 1 便の後の再測定（同じ窓・置き場は第 1 便の前と同一）: fannkuch の main k66〜121 で greedy の置き場の写しの費用が
     579 → 507（③ の写し — 理想の写しと一致。写しのギャップ 72 は全部詰まった）。1brc の main k13〜66・k35〜44 は元から写しのギャップ 0（741 / 280）。
     残る差は置き場の選び方: fannkuch 507 対 L2 の証明つき最適 90・1brc k13〜66 741 対 165・k35〜44 280 対 42 — 第 2 便（選び方）の領分
5. 重みは命令数のモデルで、cycles の代理にはならない: fannkuch のように分岐予測ミス律速の題材では、割り当ての重みの差が
   そのまま cycles に化けるとは限らない。レーンの各便はこの前提で「命令数 + 熱いコードの同一性」を
   判定の物差しにしており、cycles は配置（アラインメント・関数の先頭位置）で ±3〜4% 揺れる参考値にとどめている
6. 境界検査の消去（bce④）で起きた非単調の正体は「境目の型」: `a[i] = a[i + 1]` の 2 本目の検査を消すと検査の命令は 0.22 G 減るのに、
   消えた比較の区間が無くなったことで greedy の順序が動き、運搬値 v46 の 3 本目の部分区間が r10 を取って入口の load・出口の store がループの頻度で入った
   （fannkuch が差し引き損）。最小費用流（L1）・L2 の最適の側は単調（検査を消して悪くなることは無い）— 非単調は greedy の費用モデルの産物と証明された。
   ③で出口の store が消えた木では bce④ は fannkuch −0.19%（差し引き得）で着地した
7. 計器の注意: 1brc の instructions:u は ASLR で二峰（同じ ELF で −0.45% の下の峰がときどき出る）。命令の比較は `setarch -R` で数える
