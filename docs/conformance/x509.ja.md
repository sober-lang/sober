# X.509

[English](x509.md) · [準拠文書](README.ja.md)

## 範囲

TLS のクライアントがサーバの証明書の鎖を検証する道（RFC 5280 6 章の WebPKI の範囲）。std の内側の実装で、公開の口は `std/http/client` の https と `extraRoots:`（追加の信頼の起点）。時刻は呼び手が渡し、検証は決定的。

### x509-limbo の既知の差

x509-limbo の題材のうち、limbo の期待と判定が違うもの。どれも limbo が拒否を求め、Sober が受ける向き。この表に無い食い違いと、表にあるのに一致した題材は、テストが赤にする。

<!-- confsync:begin x509-limbo-known -->
| 分類 | 種別 | 数 | 理由 | 題材 |
|---|---|---:|---|---|
| root-anchor | 意図して | 11 | 信頼の起点（ルート）は CA の印・拡張・鍵 ID を問わない（RFC 5280 6.1 の trust anchor information — Go と同じ） | `rfc5280::ski::root-missing-ski` `rfc5280::unknown-critical-extension-root` `rfc5280::root-missing-basic-constraints` `rfc5280::root-non-critical-basic-constraints` `rfc5280::root-inconsistent-ca-extensions` `webpki::aki::root-with-aki-missing-keyidentifier` `webpki::aki::root-with-aki-authoritycertissuer` `webpki::aki::root-with-aki-authoritycertserialnumber` `webpki::aki::root-with-aki-all-fields` `webpki::aki::root-with-aki-ski-mismatch` `webpki::eku::root-has-eku` |
| issuer-rules | 意図して | 15 | 発行側（CA）が守る MUST で、検証器は強制しない（鍵 ID の欠け・critical の AKI・critical でない nameConstraints・SAN の critical と空の subject の組・空の subject の CA・20 バイト超と 0 のシリアル〔0 は NSS のルートに実在〕・EKU の critical・AIA の形〔読まない〕・先頭が点の DNS の制約 — Go と同じ） | `rfc5280::aki::critical-aki` `rfc5280::aki::leaf-missing-aki` `rfc5280::aki::intermediate-missing-aki` `rfc5280::aki::cross-signed-root-missing-aki` `rfc5280::nc::permitted-dns-match-noncritical` `rfc5280::nc::invalid-dnsname-leading-period` `rfc5280::nc::nc-forbids-othername-noop` `rfc5280::san::noncritical-with-empty-subject` `rfc5280::serial::too-long` `rfc5280::serial::zero` `rfc5280::ski::intermediate-missing-ski` `rfc5280::ca-empty-subject` `webpki::eku::ee-critical-eku` `webpki::san::san-critical-with-nonempty-subject` `webpki::malformed-aia` |
| no-cn | 意図して | 9 | CN は見ない — 「CN が SAN にあること」は発行側の規則（CA/B Forum）で、名前の照合は SAN だけ | `webpki::cn::ipv4-hex-mismatch` `webpki::cn::ipv4-leading-zeros-mismatch` `webpki::cn::ipv6-uppercase-mismatch` `webpki::cn::ipv6-uncompressed-mismatch` `webpki::cn::ipv6-non-rfc5952-mismatch` `webpki::cn::punycode-not-in-san` `webpki::cn::utf8-vs-punycode-mismatch` `webpki::cn::not-in-san` `webpki::cn::case-mismatch` |
| cabf-leaf | 意図して | 4 | CA/B Forum の leaf の規則（EKU 必須・anyEKU 禁止・CA の証明書を leaf に使わない）は焼き込みの WebPKI の起点で止まる鎖にだけ掛ける — limbo の起点は追加の起点（私的 PKI）の扱いで、RFC 5280 と Go と同じく受ける | `webpki::eku::ee-anyeku` `webpki::eku::ee-without-eku` `webpki::ee-basicconstraints-ca` `webpki::ca-as-leaf` |
| psl-wildcard | 未実装 | 2 | 広すぎるワイルドカード（*.co.uk の形）の検出は public suffix の表が要る — std は PSL を持たない（使い手だった cookie jar を退役 — 繋ぐときに表を戻す） | `webpki::san::public-suffix-multi-label-wildcard-san` `webpki::san::public-suffix-private-namespace-wildcard-san` |
<!-- confsync:end x509-limbo-known -->

limbo から抜き出すときに外した名前空間と機能（bettertls・online・CLIENT の検証・CRL・DN の nameConstraints・ポリシーの制約・ML-DSA・深さの上限の題材）は `scripts/limbo.ts` の頭に。

### 証明書の読みの Go との差

Go の crypto/x509 が読めずに拒否する証明書。Sober は処理しない部分（DSA の鍵の引き継ぎ・CRL の配布点）を読み飛ばすので、読みとしては受ける（検証では DSA の署名を Unsupported で拒否し、CRL は見ない）。
