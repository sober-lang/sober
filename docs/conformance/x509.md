# X.509

[日本語](x509.ja.md) · [Conformance](README.md)

## Scope

How the TLS client verifies the server's certificate chain (the WebPKI scope of RFC 5280 chapter 6). It is implemented inside std; the public entry points are https in `std/http/client` and `extraRoots:` (extra trust anchors). The caller passes the time, so verification is deterministic.

### Known deviations from x509-limbo

x509-limbo cases where Sober's verdict differs from limbo's expectation. In every one limbo expects a rejection and Sober accepts. A disagreement missing from this table, or a case in the table that now agrees, makes the test fail.

<!-- confsync:begin x509-limbo-known -->
| Class | Kind | Count | Reason | Cases |
|---|---|---:|---|---|
| root-anchor | by design | 11 | A trust anchor (root) is not checked for the CA flag, extensions or key IDs (RFC 5280 6.1 trust anchor information — same as Go) | `rfc5280::ski::root-missing-ski` `rfc5280::unknown-critical-extension-root` `rfc5280::root-missing-basic-constraints` `rfc5280::root-non-critical-basic-constraints` `rfc5280::root-inconsistent-ca-extensions` `webpki::aki::root-with-aki-missing-keyidentifier` `webpki::aki::root-with-aki-authoritycertissuer` `webpki::aki::root-with-aki-authoritycertserialnumber` `webpki::aki::root-with-aki-all-fields` `webpki::aki::root-with-aki-ski-mismatch` `webpki::eku::root-has-eku` |
| issuer-rules | by design | 15 | MUSTs for the issuer (CA) that a verifier does not enforce: missing key IDs, critical AKI, non-critical nameConstraints, SAN criticality vs. empty subject, CA with an empty subject, serials over 20 bytes or zero (zero occurs in NSS roots), critical EKU, AIA shape (not read), DNS constraints with a leading dot — same as Go | `rfc5280::aki::critical-aki` `rfc5280::aki::leaf-missing-aki` `rfc5280::aki::intermediate-missing-aki` `rfc5280::aki::cross-signed-root-missing-aki` `rfc5280::nc::permitted-dns-match-noncritical` `rfc5280::nc::invalid-dnsname-leading-period` `rfc5280::nc::nc-forbids-othername-noop` `rfc5280::san::noncritical-with-empty-subject` `rfc5280::serial::too-long` `rfc5280::serial::zero` `rfc5280::ski::intermediate-missing-ski` `rfc5280::ca-empty-subject` `webpki::eku::ee-critical-eku` `webpki::san::san-critical-with-nonempty-subject` `webpki::malformed-aia` |
| no-cn | by design | 9 | CN is not read — "the CN is in the SAN" is an issuer rule (CA/B Forum); names are matched against the SAN only | `webpki::cn::ipv4-hex-mismatch` `webpki::cn::ipv4-leading-zeros-mismatch` `webpki::cn::ipv6-uppercase-mismatch` `webpki::cn::ipv6-uncompressed-mismatch` `webpki::cn::ipv6-non-rfc5952-mismatch` `webpki::cn::punycode-not-in-san` `webpki::cn::utf8-vs-punycode-mismatch` `webpki::cn::not-in-san` `webpki::cn::case-mismatch` |
| cabf-leaf | by design | 4 | CA/B Forum leaf rules (EKU required, no anyEKU, no CA certificate as a leaf) apply only to chains ending at a built-in WebPKI root — limbo roots are treated as extra (private PKI) roots and accepted, as RFC 5280 and Go do | `webpki::eku::ee-anyeku` `webpki::eku::ee-without-eku` `webpki::ee-basicconstraints-ca` `webpki::ca-as-leaf` |
| psl-wildcard | not yet | 2 | Detecting over-broad wildcards (the *.co.uk shape) needs the public suffix list — std does not carry the PSL (its only user, the cookie jar, was retired — the table comes back when this is wired) | `webpki::san::public-suffix-multi-label-wildcard-san` `webpki::san::public-suffix-private-namespace-wildcard-san` |

### Parsing differences from Go

Certificates that Go's crypto/x509 refuses to parse. Sober skips the parts it does not process (inherited DSA key parameters, CRL distribution points), so it parses them (verification still rejects DSA signatures as Unsupported and never reads CRLs).
