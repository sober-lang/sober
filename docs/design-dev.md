# Sober — 設計の記録（開発者向け）

公開の設計の柱は [../DESIGN.md](../DESIGN.ja.md) に、利用者の「なぜ」は [設計ノート](design-notes/) にまとめてある。この文書は、設計の位置づけ・非目標・審査基準・決め方の型・実装計画を、決めた順に記録した開発者向けの台帳。

書くのは普通のコード、検査されるのは型システム級の性質。

Go の倹約（シグネチャ明示・package が可視性の単位・仕様が小さい）を継いだ式指向言語。
表現力を書き手への新語彙で買わず、安全性は analyzer（受理の定義に含まれる）と、スコープに閉じた寿命で買う。
名前は態度を言う: 飾らない、誇張しない、流行に飲まれない。拡張子 `.sober`。


## 一言で

値は流れ、構文は分岐せず、振る舞いはデータの外にある。

- if / switch / ブロック / for が式。全部が値を返す
- 多値は分解点まで流せる。`|>` と `_` で経路が一本の線になる
- メソッドなし、型クラスなし。interface = 関数値の struct、impl = その定数。ディスパッチはただの引数
- const デフォルト。`mut` は `while` に隔離される
- comptime なし。計算はコンパイラの外、道具（analyzer + fix）が言語に書き込む
- 全ブロックが region。寿命はスコープの入れ子に一致し、GC も借用検査も要らない
- 色なし stackful コルーチン + structured concurrency。並列スコープに渡せるのは不変値かチャネルだけ
- 効果・エラーラベルは analyzer が call graph から導出し、公開境界に宣言を強制する
- 非 null デフォルト。`nil` は `T?` にしか住めない

### 位置づけ（2026-09-17）

Rust の 2 保証（メモリ安全・データ競合自由）を借用検査なしで。加えてエラーと効果の網羅。コンパイルは Go 並み。拒否と fix が LLM の作業単位。

- Rust と同じ 2 つを region と「並列スコープには不変値かチャネルのみ」で保証する（docs/formal.md の証明対象）。ライフタイム注釈も所有権の学習曲線も無い
- Rust が捕まえない 2 種類を拒否する: エラーの取りこぼし（ラベル集合の網羅で `default: panic` と握り潰しが消える）、効果の黙った変化（「いつからネットワークを叩くようになったか」が diff とゲートに出る）
- コンパイル速度は構造で決まる: 関数内推論のみ、単相化なし、意味が最適化器に依存しない、パッケージ境界の宣言で解析が切れる。Rust 比一桁を計測で示す
- 正直な弱点: 実行速度は辞書渡しの未特化部・Handle の世代チェック・region 越境のコピーで Rust に負ける場所がある。「書き換えたら n 倍 / 1/n」は比較対象が要り、Zig 製のゲームと Go 製の自作ツール 1 本の移植で数字を取る
  - ベンチの題材: 看板は 1BRC（io + string + map のコンパイラ形ワークロード。温度は ×10 固定小数点の int — float 不要）。対照群は CLBG の binary-trees（アロケータのストレステスト — GC / malloc / region を比べる、region が構造的に有利なはずの土俵）と fannkuch-redux。参照実装が Go / Rust に揃っていて比較の正当性に説明が要らない。計測開始は正規バックエンドへの切替後（B-9 — 2026-09-27 に済み）。reverse-complement / k-nucleotide は byte 詰め表現の後、n-body 等は float の後。副作用: 1 文字 1 語の借金と byte 型の未決に期限圧力が掛かる — 例が仕様を引っ張る思想どおり
- 弱点の対: 制約の配当を取りにいく最適化方針（2026-09-19）。Sober の決定済み制約は Go にも Rust にも無い最適化のライセンスで、これをガンガン取りにいく。いずれも「意味は最も単純な 1 規則、性能は最適化器」（決め方の型 4 手目）に収まり debug ビルドで飛ばせる。インベントリ:
  - 上界の事前計算系（スタック上界計算の横展開）: コルーチンスタックを上界ぴったりで確保（guard page・プローブ不要 — Phase 5 計画済み）。region 上界の静的計算 → scope のスタック降格: ループ・可変長を含まない scope は region サイズがコンパイル時定数 — mmap でなくフレーム上の領域に降格して開閉ゼロコスト（フレーム定数 + 呼び出し深さの集計をそのまま流用）。世界が閉じるのでフレーム融合・ホットパスの sub rsp 統合が全体最適でやれる
  - region / escape 系: escape が構文で決まる → escape しない alloc のスタック昇格が解析でなく読み取り（Go の escape analysis の保守的近似が要らない）。子 region にゴミが無ければ境界コピーは region の付け替えに（1 region 1 ビルダー規律の配当 — language.md 21 節）
  - 不変性系: const キーの imm map リテラル → コンパイル時実体化（perfect hash / ソート済み配列を rodata へ — コンパイラのキーワード表が最初の受益者）。freeze 済みは並列読み同期不要。imm 要素のコピー省略（22 節）
  - エイリアス決定性系: 値ヘッダ + cap 再利用なし + 先端規則で別名解析が構文レベルに決まり load / store の並べ替え自由度が広い。mut は par 境界を越えない → フェンス・atomic 不要が自明
  - クローズドワールド + 辞書系: 間接呼び出し候補が nominal 関数型で閉じる → devirtualization / inline。`block` しない関数に検査点不要。fix が書いた辞書定数 → 選択的単相化を「意味論でなく最適化」としてやれる（単相化なしの決定と両立）
  - 検査除去 → panic-report（追加 2026-09-27、language.md 27 節）: panic フリーは文法の性質でなく検証済みプログラムの性質として狙う。mem-report と同型の `panic-report` —「このバイナリに到達可能な panic 点は N 個、場所は path:line」をリンク時に出す。analyzer の範囲証明 → 検査除去（検査済み = 最適化ライセンス）の出口を性能だけでなく言明にも使う。組み込みターゲット（panic の受け皿未決）は「panic-report = 0 を要求するターゲットプロファイル」で受けられる — 文法を変えずに panic フリー保証が機械の言明になる。棄てた案: 文法から panic を消す（refinement 型・借用検査・エラーラベルの嘘のいずれかが代金で、どれも棄却済みの方向 —「到達 = バグ」を値の世界に漏らすと `@errors` の信号が濁る）
  - 売りの言語化（2026-09-19）: GC 無しの配当は「少ない」より「予測可能」。GC ヘッドルーム（Go は実質ライブヒープの約 2 倍）・オブジェクトヘッダ・断片化が構造的に無く、コルーチンスタックは上界ぴったり（Go の初期 2KB + 成長機構と桁が違う — SoberSQL の接続あたりメモリに直結）。
    並行処理プールの言語化（2026-09-19。このセッション最大の収穫候補）: 正確な主張は「Go のプログラミングモデル（stackful・色なし）のまま、Rust async 並みのフットプリント」。対 Go — 上界ぴったり予約 + スタック成長機構そのものが不要なので morestack プロローグ（全呼び出しに乗るスタック検査）も消える: メモリと呼び出しコストの両取り。ワーカープールの典型タスク（閉じた小さい call graph）は数百バイト級で、1M タスク × 256B = 256MB vs Go の 2GB+ — 1〜2 桁大きいプールが現実になる。対 Rust — Rust async も future はぴったりサイズ（コンパイル時状態機械）なので差は大きさでなくモデル: stackless で関数に色が付く（async / Pin / Send 境界）のに対し、Sober は stackful のまま同じ数字を出す。但し書き: `@recursion` 宣言つき関数を呼ぶタスクは宣言深さ分を予約（呼ばないタスクは払わない — 上界は spawn 点ごとの call graph で決まる）、native FFI はシステムスタック切替の例外（wasm FFI はエンジン管理で例外にならない）。region 上界の静的計算が進むと最悪メモリ使用量がリンク時に出せる領域が広がる → 将来機能 `sober build --mem-report`（スタック上界 + 静的 region + 動的 region の scope 一覧のコンパイル時予算レポート。GC 言語には原理的に出せない数字）。但し書き: region のゴミは scope 出口まで滞留（倍々成長で 2 倍有界 — 「予測可能」はこの有界性込みの主張。無界候補は selfhost 検証 V2 で実測）。
    対 Rust の言語化（2026-09-19）: 「GC 無し・省メモリ」自体は Rust と同着（Rust は即時解放で定常 RSS はむしろ勝つ場面がある）。Rust に無いのは GC でなく閉じた世界 — スタック上界には (a) 再帰が機構で縛られる（`@recursion`） (b) 間接呼び出し候補が閉じる（nominal 関数型） (c) コンパイル時実行が無い、の 3 つが要り、Rust は再帰自由・`dyn` で call graph が開くため embedded 向けツール（cargo call-stack 系）も近似止まり。Sober はこの計算のために言語を設計しているので「コンパイラが保証する数字」になる。もう 1 点は「既定が arena で安全性は型が担保」（Rust の arena はライブラリ + ライフタイム体操で既定でない）+ 解放 O(1)（drop 連鎖なし — 大きな木の teardown で差が出る）。主張の正確な形: 「世界が閉じている + region が既定だから、メモリが予測可能。GC 言語には出せず、Rust では言語外の努力と近似になる数字を、コンパイラが保証として出す」— 対 Go は消費量、対 Rust は保証の形で差別化。
    対 Rust の戦線 — 速度（LLVM 不採用の配当）: 対 Rust の主張は 2 本立て — メモリは上の「保証の形」、速度は「LLVM が原理的に持てない知識 + コンパイル速度」。命令選択・レジスタ割り当て・自動ベクトル化の質では LLVM に挑まない（μカーネルのピーク性能では戦わない）。勝ち筋は ① 証明による検査除去（analyzer の範囲証明 + 検査済み = 最適化ライセンス。消えたこと自体が panic-report の言明になる — Rust の境界検査除去はヒューリスティック）② region の構造的知識（enter / alloc / leave の対が構文で見える → スタック降格。bump では確保順 = メモリ順で走査の局所性が構造的に良い — binary-trees で malloc 版に勝ち得る根拠）③ 閉世界の完全 devirt（間接呼び出し候補が常に既知 — trait object / dylib で閉じきれない Rust LTO との差）④ 効果の導出による合法な CSE / hoist ⑤ コンパイル速度を性能主張に含める（LLM の作業ループではビルド速度 = エージェントの反復速度 — Rust の最弱点で最も確実な戦場）⑥ 速度の予測可能性（下の段落）。既存の裁定の延長で、新しい賭けは増やさない
    Web サーバ / アプリへの言語化（2026-09-20 追記）: Apache の apr_pool・nginx の ngx_pool_t（リクエスト / 接続単位の pool + 一括解放）は「1 リクエスト = 1 scope = 1 region、出口で O(1) teardown」と同型 — 高性能サーバが C の規約と職人芸で守る割り当て構造が、普通にハンドラを書くだけの既定意味論。主張の正確な形は「nginx 並みの性能」（throughput は io 実装品質の変数）でなく「nginx の割り当てアーキテクチャが既定」で、対 Go の実利は GC pause ゼロのテールレイテンシ + 接続あたりメモリ（消費量の言語化にテール予測性を足す）。IO 未決を (c) thread-per-core に倒すと nginx のワーカーモデルそのものになり、割り当て構造だけでなくアーキテクチャ全体が端から端まで一致する（ワーカー固定と最も親和する候補でもある — 主張の強度が io 裁定に連動する点をここに記録）。
    組み込みへの延長（2026-09-19）: 他言語の組み込み対応は本体からの引き算（Rust の no_std、C++ freestanding）で、引き算はエコシステムを二重世界に割る。Sober は引くものが最初から無い（GC 無し・libc 非依存・syscall 最小・静的単一バイナリ・スタック上界・region が本体の意味論）ので、エコシステム全体が自動的に組み込み対応 — 主張は「組み込みが本命」でなく「サブセット無しで上（サーバ）から下（MCU）まで同じ言語」。mem-report は MCU では保証から必需品に格上げされ、region は「mmap 遅延ページ → 固定予算の静的アリーナ」の差し替えで意味論が変わらない。但し書き（現設計で組み込みに反する点）: チャネルの無限バッファ（メモリ無界 — 有界変種の未決を language.md に積んだ）、MMIO / volatile / 割り込み（`@layout` の延長線、未設計）、panic の受け皿、ターゲット（ARM / RISC-V は Phase 6）
    速度の予測可能性— mem-report と同型の軸: 最速ではなく「速度が言明できる」で戦う。GC 言語は pause と headroom で tail latency が読めず、Rust ですら最適化のヒューリスティック崖（境界検査が消えるかは書き方と LLVM の版次第）がある。Sober は「意味は最適化器に依存しない」+「検査済み = 最適化ライセンス」の 2 段で、どの検査がなぜ消えたかが証明の帰結として言える — 崖がヒューリスティックでなく裁定になる。出口は `perf-report` 構想（時間版 mem-report。決定的スケジューラ・スタック上界・region 上界と合成し「最大 N KB・検査ゼロ・pause ゼロ」を言明）。一等地は組み込み（WCET）と SoberSQL（p99）。3 本のレポート: mem-report（空間）・panic-report（失敗）・perf-report（時間）。キャッチコピー候補: 「サプライズは全部コンパイル時に、実行時はつまらない」 — Sober の名の由来として
- 第 3 の軸が本命: analyzer の拒否と fix が LLM の作業単位になっている。エージェントが書くコードでは、借用検査より網羅検査の方がバグ削減の n が大きく出るはず

## 非目標（強みの双対。2026-09-19）

向いていないユースケースはほぼ全部、強みと同じ制約の裏面として導出できる。機能要望をここで切る:

1. 動的性が主役のソフト（閉じた世界の裏面）: プラグイン、dlopen、JIT、ホットリロード常用、REPL 的探索。スタック上界・DCE 完全・mem-report は全部「リンク時に世界が閉じる」に依存し、開けた瞬間に売りが全滅する。wasm FFI は檻つきの部分緩和まで。「世界はリンク時に閉じる」は決定 2026-09-27（language.md 29 節） — プラットフォーム境界の dylib（GPU ドライバ・macOS libSystem・Windows system DLL 等）は `@native` FFI の実装詳細であってリンクモデルの例外ではない（決定。動的リンクの強いユースケースを棚卸しした結果、残るのは OS / ドライバ境界だけで、FFI の箱に閉じられる）
2. 寿命が構文に従わないメモリパターン（region = LIFO の裏面）: 相互参照が絡む長寿命の可変オブジェクトグラフ — GUI のリテインドツリー + オブザーバ、undo グラフ、イベント駆動の寿命。GC 言語の本領。Handle / Pool のはしごで書けるが「Go の見た目」から遠ざかる
3. 数値計算・HPC・ML（単相化なし + 演算子を開かない、の裏面）: 辞書渡しの未特化と演算子閉鎖で、エルゴノミクスと性能の両方が弱い。GPU は Domain 経由でカーネルは別世界。非目標と明言する
4. アロケータ職人芸の極限系（region が既定意味論、の裏面）: HFT・AAA エンジン級の自前アロケータ・レイアウト職人芸。Zig / Rust の領分で競合しない

1〜4 は意味論に根差した本質的な不向き。以下 2 つは賭けの裏面（覆る可能性を残す）:

5. 雑に書いて捨てる探索コーディング: 宣言強制・網羅検査は「後で直すから今は雑に」と正面衝突。ただし fix が「雑に書く → 機械が締める」を成立させるなら思想ごと逆転する（第 3 の軸の賭けそのもの）
   - 脱出口の構想（2026-09-19）: Dynamic Sober — Sober 埋め込み専用の動的方言。既存設計に受け口が 2 つ空いている: (a) `Value` 型（language.md 16 節）が相互運用契約そのもの —「全部の値が `Value` である Sober」と定義でき、境界の隔離と `shape[T]` 変換は決定済み (b) 閉じた世界と矛盾しない — インタプリタ（Sober 製）にとってスクリプトはコードでなくデータで、region / Pool の固定予算を与えればメモリ予算つきスクリプティング（mem-report がスクリプト込みで成立）。先例は Lua より Starlark/Go（決定的・hermetic・ロード後 freeze — freeze 意味論ごと繋がる）。ホスト言語と同じ構文（Go の見た目）なので Lua 埋め込みの二言語コスト（別構文・別データモデル・スタック API）を払わない。LLM 時代の筋 = 段階的硬化: 型を省いて書く → fix が型を書き込んで静的 Sober へ昇格（本項の賭けの実行路）。
     核の主張（2026-09-19 追記）: 振る舞いは動的、検査は静的。analyzer 層は最初から型に依存しない設計（効果導出・エラーラベル・acquire/release は構文とデータフローの解析 — 12 節の層の線引き）なので、全値 `Value` の方言にそのまま掛かる: 動的スクリプトに対して「io を叩かない」「ラベル網羅に穴」「release が無い」が静的に言え、境界は `shape[T]` 契約の静的照合（sqlshape が動的な SQL に静的判定を下すのと同じ姿勢）。ホストの region 予算と合わせて「動的スクリプトなのにメモリ予算と効果が静的保証」— 既存動的言語の「後から型を貼る」（mypy / TypeScript）と別の軸で、段階的硬化は「検査は最初から静的、型付けは最後の仕上げ」という勾配になる（入場料が型でなくなる）。同梱 analyzer によるロード時検証（2026-09-19 追記）: 静的部分の情報（公開 API の shape / 効果 / ラベル宣言 — モジュール未決 (2) の interface メタデータと同じ成果物）と analyzer をホストバイナリに同梱し、実行時にロードされるスクリプトを走らせる前に検証する — eBPF 検証器の同型・言語統合版。ホストは受け入れポリシーを自分の効果語彙で書く（「このプラグイン口は io 禁止・メモリ 1MB」）。静的単一バイナリなので同梱に動的リンク問題が無く DCE で使う検査だけ残る。mem-report と合成すればスクリプトの予算適合もロード時判定。検証器の判定はセキュリティ境界になる（eBPF verifier と同じ構図）ので、Lean 検証済みチェッカーの規律をアドミッション検証器の証明へ延長する含み。fix はロード時に使えない（拒否専用モード。fix は開発時の道具のまま）。題材の第一候補はビルドスクリプト（2026-09-19 追記）: Starlark の本家用途に戻る形で、同梱 analyzer が本領を発揮する — hermeticity（ビルドキャッシュ未決の必要条件）を効果検査で機械化（「時刻・環境変数・ネットワークを読まない」をロード時に拒否で保証 → スクリプト拡張を入れてもキャッシュキーが壊れない。Bazel が規約と sandbox で守るものを言語機構で守る）。ドッグフーディングの時期もビルドシステム整備（selfhost 前後の本線）と噛み合い、SoberSQL ストアドより繰り上がる。線引き: 既定は宣言的最小（go.mod 相当 — 決定 14 と同じ思想）を保ち、Dynamic Sober は拡張が要る側（コード生成・アセット埋め込み・カスタムステップ)の受け皿に限定 — ビルド設定の Turing 泥沼化は効果ゲートで塞ぐ。
     動機の言語化: 「ビルド = 実行なのにコンパイルが挟まる」違和感（Gradle .kts）への構造的な答え。.kts は「安全性 = 型 = コンパイル」の等式に縛られ configuration のコンパイルコストを払い、Groovy は即時性に倒して検査ゼロ — 二択に見えるのは型検査がゲートだから。検査を analyzer に分離済み（12 節）の Sober では両立する: 解釈実行は即時（スクリプトはデータのまま走る）、静的保証は analyzer パス（構文 + データフローで型検査より桁違いに軽い）、判定は内容ハッシュでキャッシュ可能 — ビルドキャッシュの CAS がビルド設定自身の検証結果もキャッシュする（Gradle が configuration cache を後付けで苦労する部分が構造から出る）。他の顧客候補: SoberSQL のストアドプロシージャ、非目標 1 のプラグイン檻
6. C エコシステムの海に乗る開発（完結の賭けの裏面）: GUI ツールキット・OS API 密結合。wasm 檻経由の FFI では借り物中心の開発はコスト高 — 引き受け済みのコスト

## 審査基準

やっていることが、そのまま書いてある — 素直に書けない機能は言語に入れない。analyzer に振るか、捨てる。（2026-09-19 改訂。旧: 「Go の見た目で書けないなら入れない」— Go 自体がおおむね素直なので代理指標として機能したが、逸脱の記録を見ると cap 再利用・map 参照ヘッダ・`v, ok :=` など「Go の形が意味に対して素直でない場所」では毎回 Go 側を棄てていた。本体の基準はこちら。「Go の見た目」は近似として引き続き有用）

倹約は美徳でなく構造材（2026-10-04 に抽出 — 性能投資とフロントエンド接合の壁打ちで、継いだ倹約に力学的な意義が三つ立った）: ①最適化の自由度の源泉 — 書かれていない機構は選び直せる・約束していない観測面は保存義務がない（倹約 = コンパイラに残される自由の量。実証 = scanb は素直なバイトループにだけ挿せた・M12 の手の語化は半分不採用）②約束の表面積の最小化 — 一級の意味論は撤回不能（Ruby の open class が JIT に永遠のガード税を課す型の罠）。糖衣は撤回可能なので、新機能は糖衣でインキュベートし、コアへの昇格に定理の関税をかける ③接合の着地点の資格 — 構文皮も別言語のフロントエンドも「Sober に落ちる」ことで検証と性能を相続する。落ちる先は小さく意味が確定しているほど良い — 倹約なコアだけがコンパイルターゲットの母艦になれる（LLVM が IR の倹約さで百言語の母艦になったのと同型・ただし相続させる財産に型と検証が含まれる）。

意味を持つものはソースにある。隠れてよいのは意味を持たない機械的なものだけ（2026-09-18 に抽出。それまでの決定から自然に立っていた第 2 の基準）。生成コードは fix がソースに書く / 注釈は拒否しか起こさない / `shape[T]` は式で参照した分だけ出てグローバルな型テーブルを持たない / 名前対応は注釈ではなく `Rename` 辞書 / comptime・AST 埋め込み・巻き戻し器・シグナルプリエンプション・GC は棄却、が全部この一つの帰結。隠れていてよいのは `Layout[T]` の暗黙渡し、defer の展開、region の push / pop、スタック切替、最適化器の特化のように、出力を理解するために読者が知る必要のないもの。理由は「LLM の作業単位」: ソースに無いものは LLM にも読者にも analyzer にも見えず、3 者が同じものを見ている状態を保つ。「暗黙に渡せば楽」という案が出たら、渡すものが意味を持つかどうかで裁く。

### 決め方の型（2026-09-17 の設計セッションから抽出）

未決を片付けるときの手順。この日の決定（キャンセル、escape、スタック上界、効果宣言、辞書解決、ジェネリクス、FFI、`@export`、Domain 越境）は全部この 5 手で済み、新しい型規則は一つも要らなかった。

1. 問いを層に割る。コンパイラ（健全性）、analyzer（拒否と提案）、最適化器（見えない変換）、std のどこの仕事かを先に決める。キャンセルは「配達と巻き戻し」、escape は「意味論と最適化」に割れた
2. 意味論は最も単純な 1 規則にする。「region 境界越えはコピー」「切られた task は検査点で止まる（キャンセルは値にならない — 2026-10-05 改訂。旧「`Cancelled` は `block` 効果のエラー面」）」「注釈は導出集合の上界」。例外や場合分けを意味論に持たない
3. エルゴノミクスは fix に振る。辞書のゼロ段解決、`Value` からの変換関数、C ヘッダ、staging への書き換え。人が打つ量を減らす手段は「言語が推論する」ではなく「道具がソースに書き込む」。生成物はビルド時の別物ではなく、レビューを通ったソース
4. 性能は最適化器に振り、意味に触れさせない。単相化、割り当て点の再標的、`get` の分岐消去。意味が最適化器に依存しないので debug ビルドは最適化器を飛ばせる
5. 新しい型規則が要ると感じたら、設計の穴の信号。既存規則の組み合わせで済まないか先に探す。acquire のピン済み参照も「region の狭め替え」で済んだ

運用: 決定を書くときは棄てた案を一行残す（後で同じ案を再検討する時間が消える）。決定が docs のどの節に依存するかを併記する。

ランタイムに無いもの（それぞれ設計上の理由で消えた）: GC（→ region）、シグナルによる非同期プリエンプション（→ バックエッジの検査点。ランタイムはフラグを持つだけ）、パニックの巻き戻し器（→ エラーは値で `?`、defer はスコープ出口にインライン展開）、型情報テーブルとリフレクション（→ `Layout[T]` と `Shape[T]` は参照された型の分だけ出る静的データ。language.md 16 節）、release のガードページ（→ スタック上界のリンク時計算）、netpoller（→ std の io と Executor）。リフレクションが無いのでリンク時の dead code elimination が完全に効き、std を厚くしてもバイナリは使った分だけ。SoberSQL を C ライブラリとして組み込むときにランタイム込みで小さく収まる根拠。

## 実装計画

- Phase 0: （オラクル: parse → print → parse の不動点、命令エンコーダは `llvm-mc` と比較。docs/oracles.md）Zig 基盤 — comptime PEG パーサージェネレータ（peg.zig）、lexer、CST→AST、AST↔JSON、x86_64 + ELF 直接生成、`build / parse / codegen` 分離。文法（grammar.zig）と AST（ast.zig）は Go 皮に作り直し
- Phase 1: （オラクル: `-O0` との差分実行。Lean 評価器が出来たらそれとも）fib が動く — if / switch 式、struct、`union`、`|>` と `_`、多値の分解、`for ... yield`、`defer`、ラムダ
  - 2026-09-18 完了（`for ... yield` を除く）。`-O0` との差分実行は比較対象が無いので `examples/*.out` の期待値で代用。`for ... yield` は Phase 2 へ送った: 価値は `Iter[T]` と `|> map |> collect` の合成にあり、型もジェネリクスも無い Phase 1 で int 専用の脱糖を書いても作り直しになる。ラムダの inline 展開機構は Phase 1 で出来ているので、型が付いた時点でその上に載せる。Phase 1 の副産物: int / struct / union だけの最小の型表（Phase 2 の Lean 型検査器が正になったら、Zig 側は脱糖とレイアウトだけを残す）
- Featherweight Sober（Phase 1 と並行可）: docs/formal.md。型検査の規則を証明済みにしてから Phase 2 に入る
- Phase 2: （オラクル: Lean 型検査器・評価器、region の poison）型検査 — 関数内推論 + 双方向型検査、`T?` flow typing、region の escape 規則、並列スコープの不変値制約、ゼロ値 / definite initialization。型検査器は Lean で書き、別プロセスとして接続する（Zig は脱糖後のコア AST を JSON で渡す）。Zig 再実装は後で、Lean 実装を差分テストのオラクルにして行う（docs/formal.md「実装との照合」）
- Phase 3: （オラクル: Pool 未返却カウンタ）std — Handle / Domain / Pool / Iter。region-domain-pool.md の 1〜4 節がここで検証される
- Phase 4: （オラクル: 計装ランタイムで観測 ⊆ 導出、fuzz でラベル観測）analyzer 第 1 本 — acquire/release の局所照合（call graph 不要）。続いて効果導出、error ラベル導出、公開境界の宣言強制 + fix
- Phase 5: （オラクル: Lean トレース照合、TLA+、スタック高水位 ≤ 上界）コルーチン + structured concurrency、`parallel scope`、チャネル。スタック上界のリンク時計算と再帰 SCC の深さカウンタ（language.md 11 節）はここで入れ、コルーチンのスタックは上界どおりに region から取る。3 段に割る。マルチスレッドは 5b で入る（5a は内部マイルストーン）
  - 5a: 1 OS スレッド。`parallel scope` は構文・型検査とも最終形だが、実行は 1 スレッド上の協調的インターリーブ。意味論（region と寿命、join、キャンセル、チャネル）をここで固める。seed 付き決定的スケジューラを最初のテスト基盤にする（切替順を再現できないと並列の反例が再現できない）
  - 5b: `parallel scope` の子を N ワーカースレッドに載せる。各ワーカーは 5a のスケジューラを 1 つ持つ。決定: タスクは生成時にワーカーへ固定され、生涯移動しない（stackful でスタックを動かさない決定、FFI のスレッドローカルと整合）。スレッド境界を越えるのはチャネル・join・不変メモリの読みの 3 つだけ。子スコープの region はそれを走らせるスレッドが確保し、解放は join の後（happens-before は join に乗る）。spawn 先は Domain の Executor で、`Policy.threads` が 1 なら 5a と同じ動き
  - 5c（実測で必要になったら）: work stealing / タスク移送。Phase 6 のゲームの移植で負荷偏りが出たら入れる。入れると「実行中にスタックと region の所有スレッドが変わる」が加わり検証コストが一桁上がるので、デフォルトは入れない
  - ランタイムの検証（Lean の 3 定理の対象外。docs/formal.md「想定するリスク」参照）: 信頼核をスケジューラ・チャネル・region 解放の 3 つに限る。5a は決定的シミュレーション → 中断点の全順序列挙、5b の前に MPMC チャネルと join バリアを TLA+ で設計検証し、実装のイベントトレース（spawn / switch / send / recv / free）を仕様に対して照合する。5a のトレースは Lean の small-step 意味論をオラクルにして比較できる（formal.md 段 2）
- バックエンド戦略（裁定 2026-09-26。Phase の外 — IR 移行のタイミングは独立に決める）: 独自 SSA IR を唯一の入力に、正規と開発時専用の 2 バックエンドを両輪で育てる
  - 独自 SSA IR: AST 直吐き codegen は IR ができるまでの暫定と位置づけた（selfhost 検証 V3〜V5 は直吐きのまま回した — IR 移行を検証 5 本のブロッカーにしない）。B-9（2026-09-27）で `sober build` の既定を IR 経路に切り替え、codegen.zig を退役させた。「制約の配当」系最適化（region 上界の静的計算 → scope のスタック降格、フレーム融合）はこの IR 層に載る。Phase 6 の wasm AOT 変換器も同じ IR に流す（wasm → IR → 正規バックエンド）— 「入力 IR を一本に」の実体 入口（B-0 裁定 2026-09-27）: IR の入力は AST。新設の lowering（src/lower*.zig）が codegen の後継で、codegen は触らず並走させ、正規経路が同等に達した段で退役させた — 意味解析の重複は移行期間だけの負債。棄てた案: コア AST から下ろす（コアは型の射影で実行の写しではない — println → unit と同じ姿勢。忠実化は desugar 出力と Lean スキーマを変える）、codegen をその場で IR 発行器に書き換える（V5 と衝突し、移行中に比べる列が消える）。解決済み AST 層を desugar と共有する案は本命の収束先として selfhost 設計に積む。IR の仕様は docs/ir.md

  - 既定の FFI は wasm。C ライブラリを wasm32 にコンパイルし、Sober のコンパイル時に wasm → x86_64 へ AOT 変換して静的リンクする（wazero の compiler mode と同型。sqlshape で libpg_query を wasm 経由にして cgo を消した前例）。宣言は `@wasm("libz.wasm")` のような注釈。効果は `block`（AOT が fuel 検査点を挿すのでキャンセルが C の中に届く）。得るもの: C の UB は線形メモリに閉じ region を壊せない（3 定理が FFI を越えて生きる）、wasm のスタックはエンジン管理なのでシステムスタック切替も上界計算の例外も不要、線形メモリは「自分の memory policy を持つ Domain」で値の受け渡しは `receive` のコピー（region 規則そのまま）、ターゲットごとの C ツールチェーン不要。払うもの: 計算ライブラリで 1.2〜2 倍程度の性能、AOT 変換器（数千行）の実装。Phase 6 の最初の成果物はこの AOT 変換器で、独自 SSA IR に流し込む（wasm → IR → 正規バックエンド。バックエンド戦略の項）
  - native FFI は `@native` で明示し、GPU ドライバとプラットフォーム API に限る。Sober は libc 非依存で syscall を直接叩くので OS 接点は std が担い、C を経由する必要があるのは wasm に落ちないものだけ。ここだけ呼び出し時にワーカーのシステムスタックへ切り替え、スタック上界計算の対象外、キャンセルは戻ってから観測。analyzer は `native` を効果として追跡し公開境界の宣言に出す
  - 逆向き: C から Sober を呼ぶ `@export(c)`（決定 2026-09-17）。SoberSQL の「組み込み可能」の実体で、Phase 6 を待たず SoberSQL の最初の公開面として先に効く。内部 ABI は自由（多値・暗黙辞書・scope・region 付き参照は C に対応物が無い）、境界だけ C ABI を持つ
    - 署名は C で表現できる部分集合に制限し、コンパイラが検査: スカラー、`@layout(c)` の struct とその参照、`(ptr, len)` に展開される slice / string。`(T, error?)` は戻り値コード + 出力引数で、`@errors` が閉じているのでエラーコード enum が機械的に決まる。`T?` は参照なら NULL 可能、値なら有無フラグ付き struct。辞書・関数型引数は不可（コールバックは `@layout(c)` の関数ポインタ型を別に定義）
    - ヘッダ `sober.h` は fix が書き、analyzer が export 署名との一致を検査する（16 節の fix 生成と同じ扱い。ビルド時生成ではなくリポジトリのファイル）
    - 不透明ハンドルは Handle そのもの（index + 世代の整数）。閉じた後の使用は UB ではなくエラーコード。DB 接続・prepared statement・カーソルを全部 Handle で渡す。SQLite の `sqlite3*` のダングリングが構成的に消える
    - ホストは別 Domain。境界を越える値は常にコピー（region 規則）。結果はホストのバッファに書くか Sober 側 region に置いて `sober_free(h)` で返す。ホストのメモリを Sober の参照で指さないので 3 定理が境界でも生きる
    - 実行文脈: (1) export 呼び出し 1 回 = 1 scope。入口で region を作り出口で解放、ホストからのキャンセルは `sober_cancel(ctx)` で scope のフラグを立てる（`sqlite3_interrupt` と同型） (2) 呼び出しをまたぐ状態は `sober_init()` が作るルート Domain の region に住み Handle で参照 (3) ホストのスタックサイズは不明なので入口で Sober 管理のスタック（上界どおりの大きさ）へ切り替える（native FFI の逆向き） (4) ホストスレッドごとに 5a のスケジューラを 1 つ持つ（ホストスレッド = 外から来たワーカー。ワーカー固定と整合し、共有は不変値かチャネルだけ。単一書き手 + CoW の SoberSQL なら読み手はどのスレッドでも不変ページを読める） (5) export 関数内で `parallel scope` を使うなら Domain の Executor が init 時に起動していること
  - 「エコシステムを Sober で完結」への移行路: C ライブラリは wasm の檻の中で使い、Sober で書き直せたものから外す。移行中もメモリ安全の穴が開かない
  - 副産物（別件として置く。ランタイムが小さく GC もリフレクションも無いので TinyGo が Go から削るものが元から無い）: (1) Sober 自身を wasm ターゲットにする道（ブラウザ） (2) マイコン（ARM Thumb / RISC-V）ターゲット。ランタイムの mmap を静的な固定 arena に、syscall シムを HAL に差し替え、スタック上界の数字でスタック全体を静的確保する（RAM 予算に合わなければリンクで落とす）。足りないのはバックエンドの実装量で、codegen の入力 IR を一本にしておけばターゲット依存部だけ足せばよい。未検討: 割り込み（Executor が interrupt である Domain と読めるか）、ヒープの静的上限（ループ内の無制限割り当てを `alloc` 効果の lint で指摘）
  - 棄てた案: native FFI のみ（C を呼んだ瞬間に全保証が消える。Go の cgo と同じ立場になる）、既存 wasm ランタイムの組み込み（wasmtime は Rust + C、wazero は Go。libc 非依存・単一バイナリの方針と合わない）
