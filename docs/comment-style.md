# コードコメントの規律

src/（compiler・std）とexamplesのコメントの書き方。コメントは利用者（コードの読み手）のためのもので、開発の記録ではない。

## 原則

**コードが示せない制約・意図だけを書く。** コードを読めば分かること、開発の経緯、正しさの弁明は書かない。

## 書くもの

- 不変条件・前提（「pは凍ったmapのヘッダを指す — 索引は確定済み」）
- コードの形からは読めない理由（「専用スロットにするのは空きリストと共用するとSROAが止まるため」）
- 単位・値域・境界の意味（「kは1..31」「長さは頭5バイト込み」）
- 参照すべき正式な文書（「規則の全体はdocs/regalloc.mdの『区間』の節」）

## 書かないもの

| 禁止 | 例 | 正しい記録先 |
|---|---|---|
| 開発史・経緯 | 「フェーズ3 R1で追加」「〜の実発から」 | コミットメッセージ・.pair |
| report番号・決定の引用 | 「report-1283参照」「ナビの決定で〜」 | 同上 |
| 宣言の名前の繰り返し | 「// buildRoundtripは往復を検証する」 | 名前を省き中身から書く（「// 往復を検証する」） |
| 次の行の実況 | 「// カウンタを増やす」の直後に `n += 1` | 書かない |
| 正しさの弁明 | 「この変更で〜が直る」 | コミットメッセージ |

言語の規則ID・機構の名前（E2-S・席Aなどlanguage.mdが定義する語）はコメントに書いてよい — それは開発史ではなく言語の概念の参照。

## docコメント（宣言の直前のコメント）

- 1文目はstdref（stdリファレンス）と `sober doc` の出力に載る — **利用者向けの文書として書く**
- 1文目の区切りは「。」または「. 」（英語のdoc用）
- 宣言自身の名前で始めない（lintが赤にする）
