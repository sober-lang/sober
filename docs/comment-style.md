# コードコメントの規律

src/（compiler・std）と examples のコメントの書き方。コメントは利用者（コードの読み手）のためのもので、開発の記録ではない。

## 原則

**コードが示せない制約・意図だけを書く。** コードを読めば分かること、開発の経緯、正しさの弁明は書かない。

## 書くもの

- 不変条件・前提（「p は凍った map のヘッダを指す — 索引は確定済み」）
- コードの形からは読めない理由（「専用スロットにするのは空き鎖と共用すると SROA が止まるため」）
- 単位・値域・境界の意味（「k は 1..31」「長さは頭 5 バイト込み」）
- 参照すべき正式な文書（「規則の全体は docs/regalloc.md の『区間』の節」）

## 書かないもの

| 禁止 | 例 | 正しい置き場 |
|---|---|---|
| 開発史・経緯 | 「段 3 R1 で追加」「〜の実発から」 | コミットメッセージ・.pair |
| report 番号・裁定の引用 | 「report-1283 参照」「ナビ裁定で〜」 | 同上 |
| 宣言の名前の繰り返し | 「// buildRoundtrip は往復を検証する」 | 名前を省き中身から書く（「// 往復を検証する」） |
| 次の行の実況 | 「// カウンタを増やす」の直後に `n += 1` | 書かない |
| 正しさの弁明 | 「この変更で〜が直る」 | コミットメッセージ |

言語の規則 ID・機構の名前（E2-S・席 A など language.md が定義する語）はコメントに書いてよい — それは開発史ではなく言語の概念の参照。

## doc コメント（宣言の直前のコメント）

- 1 文目は stdref（std リファレンス）と `sober doc` の出力に載る — **利用者向けの文書として書く**
- 1 文目の区切りは「。」または「. 」（英語の doc 用）
- 宣言自身の名前で始めない（lint が赤にする）

## 網

- 開発史の語（report 番号・日付・経緯の語）… コメント総見直し便（8519fd0e）で全数除去済み。再混入はレビューで
- 名前始まり … lint が機械で赤にする
- doc コメントの 1 文目 … stdref / clidoc の黄金が照合
