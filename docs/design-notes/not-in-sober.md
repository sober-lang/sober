# 設計ノート: 意図して入れないもの

Sober に無いもののうち、まだ作っていないのではなく、入れないと決めたものの一覧です。各項目は「入れない理由」と「代わりに何があるか」の対で、詳しい問答があるものはリンクしています。まだ実装していないもの（作る予定のもの）は [README のロードマップ](../../README.ja.md#ロードマップ--まだ実装していないもの) にあり、ここには載せません。

## 型と抽象

- メソッド — 暗黙の self と、レシーバ・メソッドの集合の規則が言語を大きくするだけだからです。代わり: 名前空間は package、カプセル化は大文字の公開、ドット記法の読みやすさはパイプ `x |> f(a)`。→ [なぜメソッドが無いのか](plain.md#なぜメソッドが無いのか)
- interface・型クラス — どの実装が使われるかが型から暗黙に決まり、呼び出しの場所に書かれないからです。代わり: 関数値を欄に持つ struct（辞書）を明示で渡す（`Ord[T]{less: …}`）。→ [なぜ interface も型クラスも無いのか](plain.md#なぜ-interface-も型クラスも無いのか)・[抽象のガイド](../guide/abstraction.ja.md)
- 継承 — 型の階層は、どの振る舞いがどこから来たかを読み手に追わせるからです。代わり: struct の入れ子と、union の variant ごとの `switch`。
- 演算子のオーバーロード — `a + b` の意味が型の宣言を見ないと決まらなくなるからです。代わり: 名前の付いた関数。演算子の意味は組み込みの型ごとに固定です（string の `+` は連結）。
- 暗黙の型変換 — 値がどこで別の型になったかがソースに見えなくなるからです。代わり: 変換は `byte(x)` のように書きます。int と bool の間にも暗黙の変換はありません。
- null — どの参照も nil でありうる型は、検査の漏れを型が教えてくれないからです。代わり: 無いかもしれない値は `T?` で、nil を確かめて絞ってから使う。→ [なぜ null でなく T? なのか](plain.md#なぜ-null-でなく-t-なのか)
- イテレータのプロトコル（`next()` を持つ値の約束） — 汎用のコンテナの層を言語に置かず、組み込みの slice / map の表現の最適化と、専用の構造の専用の関数に分けているからです。代わり: for の生成元は「最後の仮引数が `func(T)` の関数」の呼び出し（push 型）で、std/iter の `Iter[T]` も同じ形です。

## 実行とメモリ

- GC — 止まる時間とメモリの量が、プログラムの構造から読めなくなるからです。代わり: region（寿命 = スコープの入れ子）。→ [GC も借用検査も無しで、なぜメモリ安全なのか](safe.md#gc-も借用検査も無しでなぜメモリ安全なのか)
- 寿命の注釈 — 寿命を構文（スコープの入れ子）から決めるので、書き手が宣言する必要が無いからです。代わり: 書けない形（逃げる参照・共有された可変）がコンパイルエラーになる。→ [寿命の注釈が要らないのはなぜか](safe.md#寿命の注釈が要らないのはなぜか)
- 例外 — 誤りの道が関数の型に出ず、どこで捕まるかが呼び出しのグラフを辿らないと分からないからです。代わり: error の値（ラベル）を戻り値で返し、`?` と `catch` で扱う。取りこぼしは解析器が拒否します。回復しない誤りは panic です。→ [エラーの取りこぼしをどう拒否するのか](safe.md#エラーの取りこぼしをどう拒否するのか)・[panic はいつ起きるのか](safe.md#panic-はいつ起きるのか)
- トップレベルの mut と `init()` — ソースを読んでも、どこで状態が書き換わり何が実行されるかが分からないからです。代わり: トップレベルの束縛は const 式だけで、状態は値として渡す（書き換えは `mut` の仮引数として呼び出しの場所に出る）。初期化は `main` から明示で呼ぶ。
- select — 複数のチャネルのどれが先に来たかで結果が変わり、並列の出力の決定性が崩れるからです。→ [なぜ select が無いのか](safe.md#なぜ-select-が無いのか)

## 生成とリンク

- マクロ・comptime・ビルド時の実行 — 読み手がソースから意味を追えなくなる最大の源だからです。代わり: 生成が要るものは道具（`sober fix`）がソースに書き込み、普通のコードとして残す。→ [なぜマクロも comptime も無いのか](plain.md#なぜマクロも-comptime-も無いのか)
- リフレクション — 実行時に型の表を持つと、使わない型まで成果物に残り、どの型がどう読まれるかがソースから見えなくなるからです。代わり: コンパイラが参照された型の分だけ出す `shape[T]` の定数の辞書（std/json のデコーダが使う）。
- 動的リンク・dlopen・プラグイン — 世界がリンク時に閉じていることが、全プログラムの解析（スタックの上界・効果の導出・DCE）の前提だからです。→ [なぜ「世界はリンク時に閉じる」のか](minimal.md#なぜ世界はリンク時に閉じるのか)
