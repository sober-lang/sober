# 設計ノート: 平凡

[README の柱「平凡」](../../README.ja.md#平凡) と [DESIGN 2. 式指向](../../DESIGN.ja.md#2-式指向--値は流れ構文は分岐しない) の「なぜ」。

## なぜメソッドが無いのか

答え: メソッドが担っていた仕事は、別の手段で足りるからです。名前空間は package が、カプセル化は package の可視性（大文字 = 公開）が、ドット記法の読みやすさは `x |> f(a)` が担います。残るのは暗黙の self の束縛と、値 / ポインタのレシーバの規則・メソッドの集合の規則で、これは言語の面積を増やすだけでした。

棄てた案: Go のメソッド（レシーバの規則が増える）・UFCS（全部の関数が `x.f()` の候補になり、名前の解決が濁る）・拡張関数（名前の解決の入口が 2 つになる）。

関連: [言語仕様 3 節・4 節](../language.md)

## なぜ interface も型クラスも無いのか

答え: interface は「関数値を欄に持つ struct」、実装は「その struct の値（辞書）」で表せるからです。`Ord[T]{less: (a, b) => a < b}` を明示で渡します。どの実装が使われるかは呼び出しの場所に書いてあり、型から暗黙に解決する仕組みはありません。

型クラスが辞書渡しに足すのは、暗黙の解決・再帰的な合成・型ごとに 1 つの実装（コヒーレンス）の 3 つです。Sober はこれを言語に持たず、辞書の省略を道具（fix）が補う方向を取りました。

棄てた案: Rust の trait + impl ブロック・Go の暗黙の interface の満足（どの型がどの interface を満たすかが宣言に見えない）。

関連: [言語仕様 3 節・25 節](../language.md)・[ツアー 4 節](../guide/tour.ja.md#4-structunionジェネリクス辞書)

## なぜマクロも comptime も無いのか

答え: コンパイル時の計算は、読み手がソースから意味を追えなくなる最大の源だからです。Sober では「意味を持つものはソースにある」を基準にしていて、生成が要るものは道具がソースに書き込み、レビューを通った普通のコードとして残します。

棄てた案: Zig の comptime・Rust のマクロ・Go の go generate（生成物がビルドの外の別物になる）。

関連: [言語仕様 9 節](../language.md)

## なぜ if や switch が値を持つのか（三項演算子が無いのはなぜか）

答え: 値を選ぶたびに一時的な `mut` を作らずに済むからです。`x := if c { a } else { b }` は、Go の `var x T; if c { x = a } else { x = b }` の置き換えです。if が式なので三項演算子は要りません。`else` の無い if は値を持たず、文としてだけ書けます（無い場合の値を暗黙に作らない）。

関連: [言語仕様 1 節](../language.md)・[ツアー 1 節](../guide/tour.ja.md#1-値と束縛式)

## なぜ多値（タプル）を変数に入れられないのか

答え: 多値は「結果が複数ある」ことの表現で、構造を運ぶ組ではないからです。受け取れるのは分解（`a, b := f()`）とパイプの先の引数（`f() |> g(_, _)`）だけで、組のまま保存したり `.0` で取り出したりはできません。名前を持つべき組は struct で名付けます。これで匿名の積型が増えることと、エラーの扱いの先送りの両方を防いでいます。

棄てた案: 一級のタプル型（便利すぎて構造の名付けが消える）・多値を一切持たない（式指向と多値の戻りが両立しない）。

関連: [言語仕様 2 節](../language.md)

## なぜ for … yield の結果を変数に入れられないのか

答え: `for … yield` が作る遅延の列（`Iter`）は、消費する場所（パイプの先や引数の位置）で展開されるからです。変数に入れたり返したりできる「逃げる Iter」を許すと、捕捉した状態の寿命を型で追う必要が出ます。今は消費の場所でだけ使える形にとどめています。

関連: [言語仕様 7 節・25 節](../language.md)・[ツアー 3 節](../guide/tour.ja.md#3-slicemapfor)

## なぜ同じ名前で束縛し直せない（シャドーイング禁止）のか

答え: 同じ名前が場所によって別の値を指すと、読み手が追う手間が増えるからです。束縛は既定で不変なので、値を更新したい場合は `mut` を付けるか、別の名前を付けます。

関連: [構文 決定 11〜18](../syntax.md)

## なぜ書き換える引数に、呼び出しの場所でも mut と書くのか

答え: どの呼び出しが手元の変数を書き換えるかを、呼び出しの行だけで分かるようにするためです。`push3(mut xs, 7)` と書いてあれば、`xs` が変わりうるのはこの行です。同じ呼び出しに同じ変数を 2 つの mut 引数として渡す（別名）ことは拒否されます。

棄てた案: ポインタと `&x`（どこで書き換わるかが型の流れを追わないと分からない）・C# の ref を仮引数だけに書く形。

関連: [言語仕様 26 節](../language.md)・[ツアー 6 節](../guide/tour.ja.md#6-mut-引数と-freeze)

## なぜ null でなく T? なのか

答え: 「無いかもしれない」を型で区別するためです。`nil` は `T?` の値にしか住めず、使う前に `!= nil` で確かめると、その先では `T` として使えます。map の引きは `V?` を返すので、「無い」と「ゼロ値」の取り違えが起きません。

棄てた案: 全部の型に null（取り違えの温床）・Go のゼロ値の返り（無いことと 0 が区別できない）。

関連: [言語仕様 15 節・22 節](../language.md)

## なぜクロージャ（外の変数を捕まえる関数の値）が無いのか

答え: 値として持ち回れる関数は、名前つきの関数と、外を捕まえないラムダだけです。外の変数を捕まえたラムダは、関数型の引数の位置でだけ使え、呼び出しの場所で展開されます（`twice((v) => v * 3, 2)` のような形）。捕まえた環境を値として持ち回ると、その環境の寿命と共有の規則が新しい型付けの面になるため、今は持ちません。

関連: [言語仕様 8 節・25 節](../language.md)
