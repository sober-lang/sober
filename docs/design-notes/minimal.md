# 設計ノート: ミニマル

[READMEの柱「ミニマル」](../../README.ja.md#ミニマル) と [DESIGN 3. 閉世界](../../DESIGN.ja.md#3-閉世界と観測不能性--世界はリンク時に閉じる)・[4. 検証の体系](../../DESIGN.ja.md#4-検証の体系--オラクルの密度が開発の速度を決める) の「なぜ」。

## なぜ依存ゼロの単バイナリなのか

答え: コンパイラも、それが出す実行ファイルも、libcにもLLVMにも依らない静的なELFです。OSとの接点は最小のsyscallだけです。依存が無いので、配布はファイル1つで、環境の違いで壊れる場所がありません。組み込みのような環境に持っていくときも、「本体から引き算する」（Rustのno_stdのような）必要が最初からありません。

関連: [設計の記録 — 位置づけ](../design-dev.md)

## コンパイラの行数はどう数えているのか

答え: リポジトリに入っている `src/compiler/` の `.sober` のうち、テスト（`*_test.sober`）と開発道具（`src/compiler/tools/` — 各段階の出力の印字や照合のための道具）を除いたものの行数です。コメントと空行も含みます。標準ライブラリ（`src/std/`）は同じ数え方で別に数えます。ターゲットに依らない部分（構文解析・脱糖・型検査・解析器・IR・最適化）と、ターゲット（x86-64の命令選択と割り当て・ELF・Linuxのランタイム）は分けていません。今は下ろしの段階に命令選択とランタイムが混ざっていて、ファイル単位で機械的には切り分けられないためです。

## なぜZigから完全にブートストラップするのか（種のバイナリが無いのはなぜか）

答え: コンパイラが何から作られたかを、ソースだけで説明できるようにするためです。凍結したZig製の最初のコンパイラ（stage1）から、`bootstrap/` にある過去のソースのスナップショットを順にビルドし、最後のステージが今のコンパイラをビルドします。今のコンパイラで自分自身をビルドし直すと同じバイト列になる（固定点）ことも、検証の体系が毎回確認しています。種のバイナリを配る形は、出自を確認できないため採っていません。

関連: [インストール](../guide/install.ja.md)

## なぜ凍結したZig版を残しているのか

答え: ブートストラップの根であると同時に、独立した実装として照合に使うためです。Zig版は新しい機能を追わずに凍結してあり、凍結した入力（コーパス）に対して、Sober版のコンパイラと同じ判定・同じ出力を返すことを毎回照合しています。

関連: [オラクル](../oracles.md)

## なぜ「世界はリンク時に閉じる」のか

答え: 閉じていると、プログラムの全体（stdを含む）について、エラーのラベル・エフェクト（ブロックするか・ioを叩くか）・スタックの上界・到達しうるpanicの位置を、呼び出しのグラフから導けるからです。これがエラーの扱い漏れの拒否・決定的な並列・軽いtaskの土台です。代わりに、動的ロード・プラグイン・JITはありません。それらが主役のソフトは非目標です。

関連: [DESIGN — 非目標](../../DESIGN.ja.md#非目標)

## 検証の体系とは何で、なぜそこまでやるのか

答え: コンパイラの変更が通る検査の一式です（`scripts/gates.sh --full`）。自己コンパイルの固定点・ゴールデンテスト・最適化あり / なしの観測の一致・凍結したZig版との照合・独立のオラクル（GoのUTF-8の実装・GNU asの命令のエンコード）・Leanの形式モデルの検査器との照合、そして文書のコード例と `examples/` の一致まで含みます。検査が密だと、影響の全数の確認が数分で済むので、大胆な作り変えを怖がらずにできます。オラクルの密度が開発の速度の上限を決める、という考えです。

関連: [オラクル](../oracles.md)

## 何を作るのに向いていないのか

答え: 強みと同じ制約の裏面として、次は狙っていません。動的性が主役のソフト（閉じた世界の裏面）・寿命が構文に従わない長寿命の可変なオブジェクトのグラフ（GUIのリテインドツリーなど。regionの裏面）・数値計算 / HPC / ML（演算子を開かない・単相化を約束しない裏面）・アロケータの職人芸の極限（regionが既定の意味論の裏面）。

関連: [DESIGN — 非目標](../../DESIGN.ja.md#非目標)

## なぜx86-64 Linuxだけなのか

答え: 今は、言語の表面とコンパイラのコアを固めることを優先しているからです。ターゲットの部分は別会計に分けてあり、macOS・Windows・他のCPU・クロスコンパイルは、1.0（言語の約束の凍結）に向けた残りの大物です。
