# 設計ノート: ミニマル

[README の柱「ミニマル」](../../README.ja.md#ミニマル) と [DESIGN 3. 閉世界](../../DESIGN.ja.md#3-閉世界と観測不能性--世界はリンク時に閉じる)・[4. 検証の網](../../DESIGN.ja.md#4-検証の網--オラクルの密度が開発の速度を決める) の「なぜ」。

## なぜ依存ゼロの単バイナリなのか

答え: コンパイラも、それが出す実行ファイルも、libc にも LLVM にも依らない静的な ELF です。OS との接点は最小の syscall だけです。依存が無いので、配布はファイル 1 つで、環境の違いで壊れる場所がありません。組み込みのような環境に持っていくときも、「本体から引き算する」（Rust の no_std のような）必要が最初からありません。

関連: [設計の記録 — 位置づけ](../design-dev.md)

## コンパイラの「10 万行未満」はどう数えているのか

答え: 3 つに分けて数えています。コア（構文解析・脱糖・型検査・解析器・IR・最適化 — ターゲットに依らない部分）が 58,510 行で、これが 10 万行未満の主張の対象です。ターゲット（x86-64 の命令選択と割り当て・ELF・Linux のランタイム）は 11,441 行で、ISA と OS ごとの別会計です。標準ライブラリは 3,743 行で、これも別会計です（いずれも注と空行を含む行数）。プラットフォームが増えても、増えるのはターゲットの会計で、コアの数は変わりません。

## なぜ Zig から完全にブートストラップするのか（種のバイナリが無いのはなぜか）

答え: コンパイラが何から作られたかを、ソースだけで説明できるようにするためです。凍結した Zig 製の最初のコンパイラ（stage1）から、`bootstrap/` にある過去のソースのスナップショットを順に建て、最後の段が今のコンパイラを建てます。今のコンパイラで自分自身を建て直すと同じバイト列になる（固定点）ことも、検証の網が毎回確かめています。種のバイナリを配る形は、出自を確かめられないため採っていません。

関連: [インストール](../guide/install.ja.md)

## なぜ凍結した Zig 版を残しているのか

答え: ブートストラップの根であると同時に、独立した実装として照合に使うためです。Zig 版は新しい機能を追わずに凍結してあり、凍結した入力（コーパス）に対して、Sober 版のコンパイラと同じ判定・同じ出力を返すことを毎回照合しています。

関連: [オラクル](../oracles.md)

## なぜ「世界はリンク時に閉じる」のか

答え: 閉じていると、プログラムの全体（std を含む）について、エラーのラベル・効果（ブロックするか・io を叩くか）・スタックの上界・到達しうる panic の位置を、呼び出しのグラフから導けるからです。これがエラーの網羅の拒否・決定的な並列・軽い task の土台です。代わりに、動的ロード・プラグイン・JIT はありません — それらが主役のソフトは非目標です。

関連: [DESIGN — 非目標](../../DESIGN.ja.md#非目標)

## 検証の網とは何で、なぜそこまでやるのか

答え: コンパイラの変更が通る 53 本の検査です（`scripts/gates.sh --full`）。自己コンパイルの固定点・黄金のテスト・最適化あり / なしの観測の一致・凍結した Zig 版との照合・独立のオラクル（Go の UTF-8 の実装・GNU as の命令のエンコード）・Lean の形式モデルの検査器との照合、そして文書のコード例と `examples/` の一致まで含みます。網が密だと、影響の全数の確認が数分で済むので、大胆な作り変えを怖がらずにできます。オラクルの密度が開発の速度の上限を決める、という考えです。

関連: [オラクル](../oracles.md)

## 何を作るのに向いていないのか

答え: 強みと同じ制約の裏面として、次は狙っていません。動的性が主役のソフト（閉じた世界の裏面）・寿命が構文に従わない長寿命の可変なオブジェクトのグラフ（GUI のリテインドツリーなど — region の裏面）・数値計算 / HPC / ML（演算子を開かない・単相化を約束しない裏面）・アロケータの職人芸の極限（region が既定の意味論の裏面）。

関連: [DESIGN — 非目標](../../DESIGN.ja.md#非目標)

## なぜ x86-64 Linux だけなのか

答え: v0.5.0 では、言語の表面とコンパイラのコアを固めることを優先したからです。ターゲットの部分は別会計に分けてあり、macOS・Windows・他の CPU・クロスコンパイルは、1.0（言語の約束の凍結）に向けた残りの大物です。
