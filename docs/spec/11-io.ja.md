# 11. io

日本語

[目次](README.ja.md)

ioはstd/io・std/os・std/netの関数で書き、表面は同期の形（待つ間はrtが他のtaskを回す）。失敗はラベルつきのerror（7章）。開いた資源（ファイル・接続）は同一性を持つ値で、コピーできず、開いたスコープの外へ出ない。

## 11.1 一括の読み書きとエラー

I-1. `io.ReadFile(path) ([]byte, error?)`・`io.WriteFile(path, b) error?`・`io.ReadDir(path) ([]io.DirEntry, error?)`・`io.ReadStdin() ([]byte, error?)`・`io.WriteStdout(b)` / `io.WriteStderr(b)`・`os.Args() ([]string, error?)`（0番はプログラム名）。テキストとして読むなら `string(b)` の検査を通す（2章T-15）。ReadDirの並びは名前のバイト列の辞書順で、`.` / `..` を含めない。
例: [`examples/io_basic.sober`](../../examples/io_basic.sober)・[`examples/io_readdir.sober`](../../examples/io_readdir.sober)・[`examples/io_stdin.sober`](../../examples/io_stdin.sober)・[`examples/io_stdout.sober`](../../examples/io_stdout.sober)・[`examples/io_args.sober`](../../examples/io_args.sober)
決定: [language.md 28節](../language.md)

I-2. ioのエラーのラベルは `io.NotFound`・`io.Denied`・`io.Other{errno}`（閉じられない残り — 開いたバケツ）・`io.Timeout`（相手の事情 — 接続の不達・再送の尽き）・`io.Expired`（自分のscopeの期限が来た — 10章C-19）・`io.Closed`（相手がもういない）。期限を書かないプログラムでも、ioの関数の @errorsにはTimeoutとExpiredが載る。キャンセルは値にならない。
例: [`examples/io_basic.sober`](../../examples/io_basic.sober)・[`examples/net_closed.sober`](../../examples/net_closed.sober)・[`examples/task_deadline.sober`](../../examples/task_deadline.sober)
決定: [language.md 28節](../language.md)

I-3. `println` が印字できるのはint・byte（10進）・bool・string（named scalarは下地）。実引数を全部評価してから1行を書く。出力は行のバッファに溜めて改行で書く。`io.WriteStdout` などの直書きは、書く前にprintlnのバッファを出す（出る順 = 呼んだ順）。
例: [`examples/io_stdout.sober`](../../examples/io_stdout.sober)・[`examples/io_writer.sober`](../../examples/io_writer.sober)

## 11.2 開いたファイル

I-4. `f := io.Open(path)?`（か `catch`）の直後の文は `defer io.Close(f)` でなければならない。Openはこの束縛の形の外（多値の束縛・関数値・`|>`）に書けず、Closeはこのdeferの形の外に書けない（二重のclose・早すぎるcloseが形で書けない）。taskが死んでdeferが走らなくても、開いたfdはtaskの出口で閉じる。根の下の開きも同じ形 — `f := io.OpenUnder(r, rel)?` の直後は `defer io.Close(f)`・`r := io.OpenRoot(path)?` の直後は `defer io.CloseRoot(r)`。
例: [`examples/io_open.sober`](../../examples/io_open.sober)・[`examples/io_open_par.sober`](../../examples/io_open_par.sober)
拒否: [`examples/io_open_neg_unclosed.sober`](../../examples/io_open_neg_unclosed.sober)・[`examples/io_under_neg_unclosed.sober`](../../examples/io_under_neg_unclosed.sober)・[`examples/io_root_neg_unclosed.sober`](../../examples/io_root_neg_unclosed.sober)・[`examples/io_root_neg_mismatch.sober`](../../examples/io_root_neg_mismatch.sober)・[`examples/io_open_neg_defer.sober`](../../examples/io_open_neg_defer.sober)・[`examples/io_open_neg_close.sober`](../../examples/io_open_neg_close.sober)・[`examples/io_open_neg_value.sober`](../../examples/io_open_neg_value.sober)
決定: [language.md 28節](../language.md)

I-5. `io.File`・`io.Root`・`net.Listener`・`net.Conn`・`tls.Conn`・`http.client.Session`（std/http/client）は同一性を持つ型 — コピーの束縛・代入・return（開いたブロックの外へ出す）・struct / slice / map / チャネルへの格納・クロージャへの捕獲・`give:` を拒否する。捕獲の例外は `task.Run` の本体のラムダと借りの位置のラムダ（5章F-14）。番号（fd）は値にならず、intとの変換のAPIも無い。子taskへはpathを渡して子で開く。
例: [`examples/io_open.sober`](../../examples/io_open.sober)・[`examples/net_multi.sober`](../../examples/net_multi.sober)

I-6. 標準ストリームは `io.Stdin` / `io.Stdout` / `io.Stderr`（`io.Stream` の定数 — プロセスの寿命・閉じない・コピーしてよい）。書きのバッファ `io.Writer` のゼロ値は標準出力へ書き、`io.SetFile(mut w, io.Stderr)` で付け替え、`io.Flush(mut w)` で残りを出す（書きの失敗はFlushが返す）。
例: [`examples/io_writer.sober`](../../examples/io_writer.sober)
決定: [language.md 28節](../language.md)

I-7. `io.OpenUnder(r, rel)` はrの下のrelだけを開く — `..`・絶対パス・rの外を指すsymlinkは解決の途中で拒否され `io.Denied`。保証はカーネル（openat2のRESOLVE_BENEATH）が持ち、stdはrelを検査しない。rの中を指すsymlinkとrの中に留まる `..` は通る。openat2の無いカーネルでは `io.Other`。`io.Stat(f)` は開いたFileの属性 `io.FileInfo{size, modTime, kind}`（modTimeはエポックからのns・通常のファイルでなくても誤りにしない — kindで見分ける）。

## 11.3 読みのストリーム

I-8. 開いたファイルは切片ずつ読む — `for chunk <- io.Chunks(f)? { … }`（行ごとは `io.Lines(f)`・位置を指定するなら `io.ChunksAt(f, off)`）。chunkは読むだけのバイト列のView `io.Bytes` で、この反復のregionの値 — 反復の外へはコピーしてしか出ない（外の変数・フィールドに置くとコピーされる）。中身のバイト列は `io.Raw(chunk)`。失敗はfor自体が返す（6章R-7）。
例: [`examples/io_chunks.sober`](../../examples/io_chunks.sober)・[`examples/io_lines.sober`](../../examples/io_lines.sober)・[`examples/io_chunks_at.sober`](../../examples/io_chunks_at.sober)・[`examples/io_chunks_keep.sober`](../../examples/io_chunks_keep.sober)
決定: [language.md 28節](../language.md)

I-9. `io.Lines` は `\n` で割り、行末の `\r` を1つ落とし、改行の無い最後の行も渡す。切片の境目をまたぐ行だけstdがコピーする。forを途中で抜けると、通常のファイルは渡していない先読みの分だけ位置を戻す（後のChunks / ReadAllが続きから読む）。`io.ChunksAt` はファイルの位置を動かさない。
例: [`examples/io_lines.sober`](../../examples/io_lines.sober)・[`examples/io_chunks.sober`](../../examples/io_chunks.sober)・[`examples/io_chunks_at.sober`](../../examples/io_chunks_at.sober)
決定: [language.md 28節](../language.md)

## 11.4 ネットワーク

I-10. `for l <- net.Listen(addr)? { … }`・`for c <- net.Dial(addr)? { … }`・`for c <- net.Accept(l)? { … }` は失敗しうる生成元で、本体を抜けたらstdが閉じる（閉じるAPIは無い）。`for chunk <- net.Recv(c)? { … }` は届いた切片（この反復のregionの `[]byte`）を相手が閉じるまで渡し、forを抜けても配っていない分は次のRecvが続きから配る。`net.Send(c, b) error?` はカーネルが受け取るまで待つ。`net.Port(l)` は割り当てられたポート。 `net.Listen` はSO_REUSEPORTを立てる — 同じuidのプロセスは同じ番地にbindでき、到着する接続をカーネルの振り分けで分け合う（別のuidはbindできない）。
例: [`examples/net_echo.sober`](../../examples/net_echo.sober)・[`examples/net_multi.sober`](../../examples/net_multi.sober)・[`examples/net_accept_break.sober`](../../examples/net_accept_break.sober)・[`examples/net_closed.sober`](../../examples/net_closed.sober)
決定: [language.md 28節](../language.md)

I-11. `net.Serve(l, handle, budget:, conns:, reject:, region:, maxWait:)` はacceptのループを持ち、接続1本ごとにtask 1本で `handle func(net.Conn) error?` を走らせる。handleの失敗と死はServeが吸収して続ける（接続は閉じる）。同時の接続が上限を超えたら、利用者のコードを走らせずに `reject:` のバイト列を送って閉じる。`region:`（既定128 MiB）は接続のtaskのregion 1つの上限で、超えるとその接続のtaskが死ぬ（Serveが吸収する）。`maxWait:`（既定100 ms）は飽和下の待ちの上限で、acceptのループ・接続のtask（とその子）が継ぐ。走れるようになってからmaxWaitを過ぎたtaskは、期限の順に、まだ期限の来ていないtaskより先に走る（同じワーカーに違うmaxWaitのtaskが混ざると、順は積んだ順）。越えた数と量は `task.Ledger()` の `late` / `maxLate` で読める。飽和しない負荷では効かない。Serveが返るのはlistenerの失敗か、Serveを包むscopeの期限（走っている接続の決着を待ってから）。listenerの失敗の後のlはlistenしていない。
例: [`examples/net_serve.sober`](../../examples/net_serve.sober)・[`examples/net_reject.sober`](../../examples/net_reject.sober)
決定: [language.md 28節](../language.md)

## 11.5 期限と壊れ方

I-12. 期限（10章C-19）の後に呼んだioの関数はsyscallを出さずに `io.Expired` を返す。既に出したファイルのioは完了まで走る。netの待ち（accept・connect・受け・送りの空き）は期限で切れてExpiredを返す。taskが死ぬと、その下でioを待つ子孫の待ちも切れてExpiredを受ける。子は強制終了されず、次のioの関数でエラーを受けてdeferと普通のパスで巻き戻る。
例: [`examples/task_deadline.sober`](../../examples/task_deadline.sober)・[`examples/net_deadline.sober`](../../examples/net_deadline.sober)・[`examples/net_deadline_spawn.sober`](../../examples/net_deadline_spawn.sober)・[`examples/net_orphan.sober`](../../examples/net_orphan.sober)
決定: [language.md 11節・28節](../language.md)

I-13. 出力のバイト列はioの実装（io_uring・epoll・同期のsyscall）に依らない — 同じ入力・同じioの結果なら同じ出力。
例: [`examples/net_echo.sober`](../../examples/net_echo.sober)・[`examples/io_chunks_par.sober`](../../examples/io_chunks_par.sober)
決定: [language.md 28節](../language.md)

I-14. TLSの接続 `tls.Conn` の読み `for b <- tls.Recv(c)? { … }` と書き `tls.Send(c, b)` はnet.Connと同じ形だが、1点だけ違う: tls.Recvのforをbreakで途中で抜けると、その接続の読みは終わる — 次のtls.Recvは `tls.Closed` を返す（届いて配っていないrecordを持ち越さない）。
例: [`examples/tls_serve.sober`](../../examples/tls_serve.sober)
決定: [language.md 28節](../language.md)

I-15. `tls.Put(c, b)` はbを送らずに積み、`tls.Flush(c)` が積んだ分を送る（`tls.Send` = Put + Flush）。積んだ分は、tls.Recvが受けた切片1つをkへ配り終えたとき・バッチに入らない次のPutの前・Serveの出口で必ず送られ、送られる順はPutの順。
例: [`examples/http_servewith_put.sober`](../../examples/http_servewith_put.sober)
決定: [language.md 28節](../language.md)

I-16. `http.client.Open(origin, k, policy:)`（std/http/client）はoriginへの接続を1本張り（httpsなら握手まで — 期限はpolicyのtimeout）、その接続の `http.client.Session` をkに渡し、kが返ったら閉じる。kの中の `http.client.Send(s, url, …)` は同じ接続の上でリクエストとレスポンスを1往復ずつ進め、redirectは追わない（3xxをそのまま返す）。urlは `/path` か同じoriginの絶対URL（別のoriginは `http.client.BadUrl`）。相手が閉じた後・閉じで区切るレスポンスの後・`Connection: close` のレスポンスの後・往復の途中の失敗の後のSendは `http.client.Closed` を返す。接続の状態（TLSの鍵と番号・受けて配っていないバイト）はSessionの値の外に住む — 値のコピーは構文で拒否される（I-5）ので、同じ鍵と番号で二つの平文を封じる形が書けない。
例: [`examples/http_client_session.sober`](../../examples/http_client_session.sober)
決定: [language.md 28節](../language.md)
