# 11. io

日本語

[目次](README.ja.md)

io は std/io・std/os・std/net の関数で書き、表面は同期の形（待つ間は rt が他の task を回す）。失敗はラベルつきの error（7 章）。開いた資源（ファイル・接続）は同一性を持つ値で、写せず、開いたスコープの外へ出ない。

## 11.1 一括の読み書きとエラー

I-1. `io.ReadFile(path) ([]byte, error?)`・`io.WriteFile(path, b) error?`・`io.ReadDir(path) ([]io.DirEntry, error?)`・`io.ReadStdin() ([]byte, error?)`・`io.WriteStdout(b)` / `io.WriteStderr(b)`・`os.Args() ([]string, error?)`（0 番はプログラム名）。テキストとして読むなら `string(b)` の検査を通す（2 章 T-15）。ReadDir の並びは名前のバイト列の辞書順で、`.` / `..` を含めない。
例: [`examples/io_basic.sober`](../../examples/io_basic.sober)・[`examples/io_readdir.sober`](../../examples/io_readdir.sober)・[`examples/io_stdin.sober`](../../examples/io_stdin.sober)・[`examples/io_stdout.sober`](../../examples/io_stdout.sober)・[`examples/io_args.sober`](../../examples/io_args.sober)
決定: [language.md 28 節](../language.md)

I-2. io のエラーのラベルは `io.NotFound`・`io.Denied`・`io.Other{errno}`（閉じられない残り — 開いたバケツ）・`io.Timeout`（相手の事情 — 接続の不達・再送の尽き）・`io.Expired`（自分の scope の期限が来た — 10 章 C-19）・`io.Closed`（相手がもういない）。期限を書かないプログラムでも、io の口の @errors には Timeout と Expired が載る。キャンセルは値にならない。
例: [`examples/io_basic.sober`](../../examples/io_basic.sober)・[`examples/net_closed.sober`](../../examples/net_closed.sober)・[`examples/task_deadline.sober`](../../examples/task_deadline.sober)
決定: [language.md 28 節](../language.md)

I-3. `println` が印字できるのは int・byte（10 進）・bool・string（named scalar は下地）。実引数を全部評価してから 1 行を書く。出力は行のバッファに溜めて改行で書く。`io.WriteStdout` などの直書きは、書く前に println のバッファを出す（出る順 = 呼んだ順）。
例: [`examples/io_stdout.sober`](../../examples/io_stdout.sober)・[`examples/io_writer.sober`](../../examples/io_writer.sober)
拒否: [`examples/println_opt.sober`](../../examples/println_opt.sober)
決定: [language.md 28 節](../language.md)

## 11.2 開いたファイル

I-4. `f := io.Open(path)?`（か `catch`）の直後の文は `defer io.Close(f)` でなければならない。Open はこの束縛の形の外（多値の束縛・関数値・`|>`）に書けず、Close はこの defer の形の外に書けない（二重の close・早すぎる close が形で書けない）。task が死んで defer が走らなくても、開いた fd は task の出口で閉じる。根の下の開きも同じ形 — `f := io.OpenUnder(r, rel)?` の直後は `defer io.Close(f)`・`r := io.OpenRoot(path)?` の直後は `defer io.CloseRoot(r)`。
例: [`examples/io_open.sober`](../../examples/io_open.sober)・[`examples/io_open_par.sober`](../../examples/io_open_par.sober)
拒否: [`examples/io_open_neg_unclosed.sober`](../../examples/io_open_neg_unclosed.sober)・[`examples/io_under_neg_unclosed.sober`](../../examples/io_under_neg_unclosed.sober)・[`examples/io_root_neg_unclosed.sober`](../../examples/io_root_neg_unclosed.sober)・[`examples/io_root_neg_mismatch.sober`](../../examples/io_root_neg_mismatch.sober)・[`examples/io_open_neg_defer.sober`](../../examples/io_open_neg_defer.sober)・[`examples/io_open_neg_close.sober`](../../examples/io_open_neg_close.sober)・[`examples/io_open_neg_value.sober`](../../examples/io_open_neg_value.sober)
決定: [language.md 28 節](../language.md)

I-5. `io.File`・`io.Root`・`net.Listener`・`net.Conn`・`tls.Conn` は同一性を持つ型 — 写しの束縛・代入・return（開いたブロックの外へ出す）・struct / slice / map / チャネルへの格納・閉包への捕獲・`give:` を拒否する。捕獲の例外は `task.Run` の本体のラムダと借りの位置のラムダ（5 章 F-14）。番号（fd）は値にならず、int との変換の口も無い。子 task へは path を渡して子で開く。
例: [`examples/io_open.sober`](../../examples/io_open.sober)・[`examples/net_multi.sober`](../../examples/net_multi.sober)
拒否: [`examples/io_open_neg_copy.sober`](../../examples/io_open_neg_copy.sober)・[`examples/io_open_neg_return.sober`](../../examples/io_open_neg_return.sober)・[`examples/io_open_neg_hold.sober`](../../examples/io_open_neg_hold.sober)・[`examples/io_open_neg_capture.sober`](../../examples/io_open_neg_capture.sober)・[`examples/io_open_neg_give.sober`](../../examples/io_open_neg_give.sober)・[`examples/net_neg_copy.sober`](../../examples/net_neg_copy.sober)・[`examples/net_neg_capture.sober`](../../examples/net_neg_capture.sober)・[`examples/tls_neg_copy.sober`](../../examples/tls_neg_copy.sober)・[`examples/tls_neg_field.sober`](../../examples/tls_neg_field.sober)・[`examples/io_root_neg_copy.sober`](../../examples/io_root_neg_copy.sober)・[`examples/io_root_neg_capture.sober`](../../examples/io_root_neg_capture.sober)
決定: [language.md 28 節](../language.md)

I-6. 標準ストリームは `io.Stdin` / `io.Stdout` / `io.Stderr`（`io.Stream` の定数 — プロセスの寿命・閉じない・写してよい）。書きのバッファ `io.Writer` のゼロ値は標準出力へ書き、`io.SetFile(mut w, io.Stderr)` で付け替え、`io.Flush(mut w)` で残りを出す（書きの失敗は Flush が返す）。
例: [`examples/io_writer.sober`](../../examples/io_writer.sober)
決定: [language.md 28 節](../language.md)

I-7. `io.OpenUnder(r, rel)` は r の下の rel だけを開く — `..`・絶対パス・r の外を指す symlink は解決の途中で拒否され `io.Denied`。保証はカーネル（openat2 の RESOLVE_BENEATH）が持ち、std は rel を検査しない。r の中を指す symlink と r の中に留まる `..` は通る。openat2 の無いカーネルでは `io.Other`。`io.Stat(f)` は開いた File の属性 `io.FileInfo{size, modTime, kind}`（modTime はエポックからの ns・通常のファイルでなくても誤りにしない — kind で見分ける）。
例: [`examples/io_open_under.sober`](../../examples/io_open_under.sober)・[`examples/io_stat.sober`](../../examples/io_stat.sober)
決定: [language.md 28 節](../language.md)

## 11.3 読みのストリーム

I-8. 開いたファイルは切片ずつ読む — `for chunk <- io.Chunks(f)? { … }`（行ごとは `io.Lines(f)`・位置を指定するなら `io.ChunksAt(f, off)`）。chunk は読むだけのバイト列の View `io.Bytes` で、この反復の region の値 — 反復の外へは写してしか出ない（外の変数・欄に置くと写る）。中身のバイト列は `io.Raw(chunk)`。失敗は for 自体が返す（6 章 R-7）。
例: [`examples/io_chunks.sober`](../../examples/io_chunks.sober)・[`examples/io_lines.sober`](../../examples/io_lines.sober)・[`examples/io_chunks_at.sober`](../../examples/io_chunks_at.sober)・[`examples/io_chunks_keep.sober`](../../examples/io_chunks_keep.sober)
決定: [language.md 28 節](../language.md)

I-9. `io.Lines` は `\n` で割り、行末の `\r` を 1 つ落とし、改行の無い最後の行も渡す。切片の境目をまたぐ行だけ std が写す。for を途中で抜けると、通常のファイルは渡していない先読みの分だけ位置を戻す（後の Chunks / ReadAll が続きから読む）。`io.ChunksAt` はファイルの位置を動かさない。
例: [`examples/io_lines.sober`](../../examples/io_lines.sober)・[`examples/io_chunks.sober`](../../examples/io_chunks.sober)・[`examples/io_chunks_at.sober`](../../examples/io_chunks_at.sober)
決定: [language.md 28 節](../language.md)

## 11.4 ネットワーク

I-10. `for l <- net.Listen(addr)? { … }`・`for c <- net.Dial(addr)? { … }`・`for c <- net.Accept(l)? { … }` は失敗しうる生成元で、本体を抜けたら std が閉じる（閉じる口は無い）。`for chunk <- net.Recv(c)? { … }` は届いた切片（この反復の region の `[]byte`）を相手が閉じるまで渡し、for を抜けても配っていない分は次の Recv が続きから配る。`net.Send(c, b) error?` はカーネルが受け取るまで待つ。`net.Port(l)` は割り当てられたポート。
例: [`examples/net_echo.sober`](../../examples/net_echo.sober)・[`examples/net_multi.sober`](../../examples/net_multi.sober)・[`examples/net_accept_break.sober`](../../examples/net_accept_break.sober)・[`examples/net_closed.sober`](../../examples/net_closed.sober)
決定: [language.md 28 節](../language.md)

I-11. `net.Serve(l, handle, budget:, conns:, reject:, region:)` は accept のループを持ち、接続 1 本ごとに task 1 本で `handle func(net.Conn) error?` を走らせる。handle の失敗と死は Serve が吸収して続ける（接続は閉じる）。同時の接続が天井を超えたら、利用者のコードを走らせずに `reject:` のバイト列を送って閉じる。`region:`（既定 128 MiB）は接続の task の region 1 つの上限で、超えるとその接続の task が死ぬ（Serve が吸収する）。
例: [`examples/net_serve.sober`](../../examples/net_serve.sober)・[`examples/net_reject.sober`](../../examples/net_reject.sober)
決定: [language.md 28 節](../language.md)

## 11.5 期限と壊れ方

I-12. 期限（10 章 C-19）の後に開いた io の口は syscall を出さずに `io.Expired` を返す。既に出したファイルの io は完了まで走る。net の待ち（accept・connect・受け・送りの空き）は期限で切れて Expired を返す。task が死ぬと、その下で io を待つ子孫の待ちも切れて Expired を受ける。子は倒されず、次の io の口でエラーを受けて defer と普通の道で巻き戻る。
例: [`examples/task_deadline.sober`](../../examples/task_deadline.sober)・[`examples/net_deadline.sober`](../../examples/net_deadline.sober)・[`examples/net_deadline_spawn.sober`](../../examples/net_deadline_spawn.sober)・[`examples/net_orphan.sober`](../../examples/net_orphan.sober)
決定: [language.md 11 節・28 節](../language.md)

I-13. 出力のバイト列は io の実装（io_uring・epoll・同期の syscall）に依らない — 同じ入力・同じ io の結果なら同じ出力。
例: [`examples/net_echo.sober`](../../examples/net_echo.sober)・[`examples/io_chunks_par.sober`](../../examples/io_chunks_par.sober)
決定: [language.md 28 節](../language.md)

I-14. TLS の接続 `tls.Conn` の読み `for b <- tls.Recv(c)? { … }` と書き `tls.Send(c, b)` は net.Conn と同じ形だが、1 点だけ違う: tls.Recv の for を break で途中で抜けると、その接続の読みは終わる — 次の tls.Recv は `tls.Closed` を返す（届いて配っていない record を持ち越さない）。
例: [`examples/tls_serve.sober`](../../examples/tls_serve.sober)
決定: [language.md 28 節](../language.md)
