# 11. io

日本語

[目次](README.ja.md)

ioはstd/io・std/os・std/netの関数で書き、表面は同期の形（待つ間はrtが他のtaskを回す）。失敗はラベルつきのerror（7章）。開いた資源（ファイル・接続）は同一性を持つ値で、コピーできず、開いたスコープの外へ出ない。

## 11.2 開いたファイル

## 11.3 読みのストリーム

I-8. 開いたファイルは切片ずつ読む — `for chunk <- io.Chunks(f)? { … }`（行ごとは `io.Lines(f)`・位置を指定するなら `io.ChunksAt(f, off)`。範囲を1つの列で読むなら `io.ReadAt(f, off, n)` — EOFまでにnバイト無ければ短い列を返す）。chunkは読むだけのバイト列のView `io.Bytes` で、この反復のregionの値 — 反復の外へはコピーしてしか出ない（外の変数・フィールドに置くとコピーされる）。中身のバイト列は `io.Raw(chunk)`。失敗はfor自体が返す（6章R-7）。

## 11.4 ネットワーク

I-10. `for l <- net.Listen(addr)? { … }`・`for c <- net.Dial(addr)? { … }`・`for c <- net.Accept(l)? { … }` は失敗しうる生成元で、本体を抜けたらstdが閉じる（閉じるAPIは無い）。`for chunk <- net.Recv(c)? { … }` は届いた切片（この反復のregionの `[]byte`）を相手が閉じるまで渡し、forを抜けても配っていない分は次のRecvが続きから配る。`net.Send(c, b) error?` はカーネルが受け取るまで待つ。`net.Port(l)` は割り当てられたポート。addrの形は `host:port`・`[v6]:port`・`[v6%zone]:port`・`:port` で、角括弧の無いIPv6の番地は `net.Bad`。listenの `0.0.0.0` はIPv4だけ、`[::]` はIPv6だけ、ホストを省いた `:port` は両方を受ける（IPv6の無いカーネルではIPv4だけ）。Dialは名前から引いた番地をIPv6とIPv4の交互（IPv6が先）に並べて順に試し、最後以外の試行は2秒で打ち切る。 `net.Listen` はSO_REUSEPORTを立てる — 同じuidのプロセスは同じ番地にbindでき、到着する接続をカーネルの振り分けで分け合う（別のuidはbindできない）。
例: [`examples/net_echo.sober`](../../examples/net_echo.sober)・[`examples/net_dualstack.sober`](../../examples/net_dualstack.sober)・[`examples/net_multi.sober`](../../examples/net_multi.sober)・[`examples/net_accept_break.sober`](../../examples/net_accept_break.sober)・[`examples/net_closed.sober`](../../examples/net_closed.sober)
決定: [language.md 28節](../language.md)

I-11. `net.Serve(l, handle, budget:, conns:, reject:, region:)` はacceptのループを持ち、接続1本ごとにtask 1本で `handle func(net.Conn) error?` を走らせる。handleの失敗と死はServeが吸収して続ける（接続は閉じる）。入場が天井に達したとき、`reject:` があれば、利用者のコードを走らせずにそのバイト列を送って閉じる。無ければ受け付けを止めず、受けた接続をlistenerごとのランタイムの列で待たせる。列が上限を越えたら1本を閉じる（shedに数える）。閉じるのは、まだ1バイトも受けていない接続の古い順で、無ければ列の頭から8本のうち未読のバイト数がいちばん多い接続（同じなら古い方）。空きができたら列のいちばん新しい接続から入れる（入場の順はioの入力）。入場を待つ接続があるとき（HTTP/2の接続の中で入場の空きを待つストリームと、本文の受けで天井の空きを待つtaskも、入場を待つ者に数える）は、入場済みの接続を切って枠を空ける。走っているストリームか待っているストリームを持つHTTP/2の接続は切らない。切る順は、前の走査（約0.27秒ごと）から1バイトも受けていない接続（待機中のkeep-aliveと止まった相手）の古い順、次に受けの速さが遅い順。満杯でないときは切らない。切った数はプールの節の `evicted` に数え、`timeout` には数えない（10章C-18）。ランタイムの列と枠を空けることは、ringを作らない構成（epollの経路）でも同じ。待っている間に何も送らずに去った接続（FINだけ・RST）は、handlerを走らせずに閉じる。`net.Waiting()` は、このプロセスのServeが受け付けを待たせている接続の数（`waiting`）と待ち行列の大きさの和（`limit`）を、読んだ時点の値で返す（エフェクトはtask.Ledgerと同じnondet）。入場はバイトの天井で決まる: `conns:` を書けば (`budget:` + task.Fixed()) × `conns:` × 2（本数の天井も `conns:` — 数えるのは接続のtaskだけで、接続のtaskが生む子は本数に数えない）。2倍のうち1つ分は接続ごとの進行の保証の余白で、天井は全部の接続が自分の子を1本ずつ、接続の予約と同じ大きさで同時に走らせる量を持つ（余白は接続の間で分け合う）、書かなければServeの開始の時点の根の天井の残りから、listenerの待ち行列とランタイムの列の分（カーネルの分 × 本数）を引いた量（本数の天井なし）。`conns:` は根の天井を越えても詰めず、何も出さない。listenerのbacklogは、根の天井の残りから導いた値に置き直す。受け付けた接続の受信バッファは、読んだ量の累計が32 KiBを越えた時点（epollの経路では受け付けた時点）で64 KiBに固定する。接続のtaskを入れるプールの天井は、このバイトの天井に、ワーカー数 × ワーカーごとの作業の分（ワーカーで走っているtaskが予約を越えて借りる分）を足した量。`http.server.ServeConn` は `Content-Length` の本文を待ち始めるとき、本文の分を先にまとめて借り、天井が埋まっていれば空きを来た順に `bodyWait:` まで待つ（10章C-18）。`region:`（既定128 MiB）は接続のtaskのregion 1つの上限で、超えるとその接続のtaskが死ぬ（Serveが吸収する）。接続のtaskは、同じワーカーの中では走れるようになった順に走る（ワーカーごとのFIFO）。例外は、HTTP/2の接続のtaskがストリームの子を走らせた後の順（10章C-14）。Serveが返るのはlistenerの失敗か、Serveを包むscopeの期限（走っている接続の決着を待ってから）。acceptの一時的な失敗では返らずに受け直す。fdの上限（EMFILE・ENFILE）とカーネルのメモリ（ENOBUFS・ENOMEM）は待ってから（5 msから失敗のたびに2倍・上限1秒）、相手が受け付けの前に去った形（ECONNABORTED）は待たずに受け直し、受け直した回数をプールの節の `acceptRetry` に数える（10章C-18）。資源が尽きた形は、続いた失敗の始まりにstderrへ診断を1行出す（10秒に1行まで）。listenerの失敗の後のlはlistenしていない。
例: [`examples/net_serve.sober`](../../examples/net_serve.sober)・[`examples/net_reject.sober`](../../examples/net_reject.sober)
決定: [language.md 28節](../language.md)

## 11.5 期限と壊れ方

I-12. 期限（10章C-19）の後に呼んだioの関数はsyscallを出さずに `io.Expired` を返す。既に出したファイルのioは完了まで走る。netの待ち（accept・connect・受け・送りの空き）は期限で切れてExpiredを返す。taskが死ぬと、その下でioを待つ子孫の待ちも切れてExpiredを受ける。scopeの子が死ぬと、scopeの本体が出口に着いて子を待っている間だけ、そのscopeの下でioを待つtask（兄弟とその子孫。生んだ順に依らない）の待ちも同じに切れる。本体が走っている間は切れない（本体が死をTryで見て続けられる）。子は強制終了されず、次のioの関数でエラーを受けてdeferと普通のパスで巻き戻る。

I-14. `tls.Serve(addr, cfg, k)` はhandshakeを済ませた接続だけを `k func(c net.Conn) error?` に渡す。cはTLSの状態を持つnet.Connで、`net.Recv`・`net.Send`・`net.Put`・`net.Flush` が暗号化して読み書きする — 平文の接続と同じ関数・同じ規則（net.Recvのforをbreakで抜けた後も、次のnet.Recvが続きを読む）。受けの誤りは、相手のfatal alertと閉じた後が `io.Closed`、壊れたrecord（こちらがalertを送って閉じる）が `io.Other{errno: 71}`。相手のclose_notifyは相手の書く側だけを閉じ、net.Recvの列を終える。その後も送れる。こちらの書く側は、kが返った後のclose_notifyで閉じる。fatalのalertを送った・受けた後の送りは `io.Closed` を返す。`tls.Protocol(c)` はALPNで決まったプロトコル（`"h2"`・`"http/1.1"`・無ければ `""`。平文の接続は `""`）。tls.Serveの握手は、非対称の計算（ClientHelloへの返事の鍵の共有と署名）の直前に、ワーカーごとの署名の列で順番を待つ。署名の列のtaskは、実行待ちの列から一定の本数を取るごとに1本と、実行待ちの列が空のときに走る（同じワーカーの他のtaskの待ちに、署名は一定の本数ごとに1回だけ足される）。待つ間も `headWait:` が効き、期限が過ぎた接続は何も送らずに閉じる。`tls.DangerouslyAllowTls12(cfg)` を通したConfigの `tls.Serve` は、TLS 1.3を申し出ないClientHelloをTLS 1.2で受ける（1.3を申し出る相手は1.3。完全なhandshakeだけ — 再開・再交渉・クライアント証明書なし。ALPNでh2に決まる接続はECDHE + AEADのスイートだけ）。1.2の握手は、ClientHelloへの返事とClientKeyExchangeの非対称の計算の両方の直前に、同じ署名の列で順番を待つ。サーバーの署名と1.2のスイートの集合は、Configの鍵の種類で決まる。RSAの鍵はrsa_pss_rsae_sha256（1.2ではrsa_pkcs1も）とECDHE-RSA・RSA鍵交換のスイート、P-256のECDSAの鍵はecdsa_secp256r1_sha256とECDHE-ECDSAのスイートを使う。
例: [`examples/tls_serve.sober`](../../examples/tls_serve.sober)

I-15. `net.Put(c, b)` はbを送らずに積み、`net.Flush(c)` が積んだ分を送る（`net.Send` = Put + Flush）。平文の接続では積まずに送る（PutはSendと同じ・Flushは何もしない）。TLSの接続では、積んだ分はnet.Recvが受けた切片1つをkへ配り終えたとき・バッチに入らない次のPutの前・tls.Serveの出口で必ず送られ、送られる順はPutの順。net.Recvのforをbreakで抜けると、その切片の後の送りは次のnet.Recvの最初の周・Flush・Send・接続の出口が受け持つ。
例: [`examples/web_server_tls.sober`](../../examples/web_server_tls.sober)
決定: [language.md 28節](../language.md)

I-16. `http.client.Open(origin, k, policy:)`（std/http/client）はoriginへの接続を1本張り（httpsなら握手まで — 期限はpolicyのtimeout）、その接続の `http.client.Session` をkに渡し、kが返ったら閉じる。kの中の `http.client.Send(s, url, …)` は同じ接続の上でリクエストとレスポンスを1往復ずつ進め、redirectは追わない（3xxをそのまま返す）。urlは `/path` か同じoriginの絶対URL（別のoriginは `http.client.BadUrl`）。相手が閉じた後・閉じで区切るレスポンスの後・`Connection: close` のレスポンスの後・往復の途中の失敗の後のSendは `http.client.Closed` を返す。接続の状態（TLSの鍵と番号・受けて配っていないバイト）はSessionの値の外に住む — 値のコピーは構文で拒否される（I-5）ので、同じ鍵と番号で二つの平文を封じる形が書けない。

I-17. `http.server.ServeConn` の `headWait:`・`bodyWait:`・`sendWait:` と `tls.Serve` の `headWait:` は、相手が送り終える・受け終えるのを待つ時間の上限（Serveの期限）。headWaitは、ServeConnに入った時刻と前のレスポンスを送り終えた時刻から次のリクエストの頭が揃うまで（keep-aliveの待ちを含む・既定30秒）。bodyWaitは、頭が揃ってから本文を受け終えるまで（既定60秒）。sendWaitは、送りが1バイトも進まない間隔（既定60秒）。tls.ServeのheadWaitは、受けてからhandshakeが済むまで（既定30秒）。期限なしは書けず、0以下は開いた時点で期限切れ。routeの実行中は効かない。期限が来たら、待っていた受け・送りが `io.Timeout` で戻り、相手には何も送らずに閉じる。scopeの期限（10章C-19）とは別のもので、どちらも効く。期限は早くは効かず、最大で約2秒遅れて効く。HTTP/2の接続（ServeConnの `proto:` でH2かBoth）では、headWaitは走っているストリームが1本も無い間の受けの待ち（接続の頭のSETTINGSを含む）に効き、ストリームの子が走っている間は効かない。bodyWaitはストリームの単位では効かない。sendWaitは、窓が開かず送れない応答を持つ間、最後に送りが進んだ時刻から数えて効き（相手のフレームが届いても延びない）、来たら接続を何も送らずに閉じる。送りがカーネルで詰まって待つ間は、HTTP/1.1と同じ送りの間隔として効く。

I-18. `http.server.ServeConn(c, route, proto:)` の `proto:` は応じるプロトコル。`http.server.H1`（省略時）はHTTP/1.1だけで、HTTP/2の接続の前置きには505を返す。`http.server.H2` はHTTP/2（h2c — 事前知識）だけで、最初の24バイトが前置き `PRI * HTTP/2.0\r\n\r\nSM\r\n\r\n` でなければGOAWAY（PROTOCOL_ERROR）を送って閉じる。`http.server.Both` は前置きならHTTP/2、でなければHTTP/1.1で応じる。ただし先頭の行が `PRI * HTTP/2.0` で残りが前置きと違えば、GOAWAY（PROTOCOL_ERROR）を送って閉じる。TLSの接続（I-14）では前置きで見分けず、ALPNで決める。HTTP/2のストリームの子（routeを呼ぶtask）が死ぬか切られて応答を終えなかったら、そのストリームにRST_STREAM（INTERNAL_ERROR）を送って枠を空け、接続は続ける: H2はHTTP/2・BothはALPNが `h2` ならHTTP/2でなければHTTP/1.1・H1はHTTP/1.1（RFC 9113 3.2）。HTTP/2に決まった接続の最初のバイトが前置きでなければGOAWAY（PROTOCOL_ERROR）を送って閉じる。HTTP/2ではストリーム1本ごとに子のtaskがrouteを呼ぶ。routeとnet.Serveのhandleは、protoによらず、mutの束縛とmutの中身を捕獲できない（呼び出し点で拒否 — 10章C-2）。相手が求めに返すだけの制御フレーム（SETTINGSとPINGのACK）を、応答を送り終えたストリームの間に1万を越えて求めたら、GOAWAY（ENHANCE_YOUR_CALM）を送って閉じ、プールのshedに数える。相手の誤りでこちらが送るRST_STREAM（ストリームの誤り・REFUSED_STREAM）は、一度に1000本まで・約0.54秒ごとに20本回復する予算で数え、尽きたら同じく閉じてshedに数える。進まないフレーム（長さ0のDATA〔END_STREAMなし〕と長さ0のCONTINUATION〔END_HEADERSなし〕）を、中身のあるフレームを挟まずに2つ続けて送った相手と、1つのヘッダのブロックがmaxHead × 4 + 16 KiBを越えた相手も、同じく閉じてshedに数える。
