## フェーズ3 R2 — 格納場所と α・β（lower/bcache.sober）

- **格納場所**: `<cacheDir>/sober-build-1/<コンパイラの鍵の先頭 16 桁>/`（鍵 = bin/soberのSOBER_SELF_KEYか、実行ファイルのワード単位の混ぜ2本 — SHA-256は10 MBで約0.8 G命令）。buildごとに外れた値を1つのパック `<pid>-<uuid>.pack` に（tmp + rename・不変）。パック = 値の並び + 索引（varintの [境界, 鍵h1, h2, 位置, 長さ, 値の検査和]）+ 尾24 B（マジック・索引の長さ・索引の検査和）。読み込みは世代の全パックの索引を表にし、当たりの値を検査和で確認してから使う
- **α**（鍵 = B1の入力）: 値 = B1の後の本体の詰めた形（mvPack）の正準形 — 外を指すワード（K_FN / K_GLOB・札つきの定数）だけ安定な鍵のハッシュへ。W1は本体を壊さずにヒープから直に同じバイト列を作る（bcAlphaHeap — 検証モードで詰めるパスと照合）・W ≥ 2はバッチの子が詰めた形に相乗り。当たりは読み戻してmvUnpack（バッチの子の結果と同じパス）
- **β1**（鍵 = B2の入力）: 値 = B2の後の呼び出し / 番地取りの相手の列。当たりの関数はB2を飛ばし（本体は入力のまま）、cutInsertの到達性と番地取りのフラグをこの列で組む。切替 / 罠を持つ関数は書かない（毎回）
- **β2**（鍵 = ckBeta）: 値 = 機械語（吐き始め〔整列の後〕から出した長さまで — 入口はキャッシュラインの跨ぎの詰め物の分だけ後ろでありうるので入口の位置も持つ）+ 後埋めの列（安定な鍵）+ xmmの組。機械語は後埋めの後のELFから切り出して後埋めのフィールドを0に戻す。β1が当たって β2が外れた関数は、x86の凍結の前にB2と検査点を遅れて掛けて検証する
- **検証モード**（SOBER_CACHE_VERIFY=1）: 何も飛ばさずに作り、格納場所に同じ鍵があればバイトで比べる（違えば `cache: stale entry <切り口> <鍵>` で落ちる）。SOBER_CACHE_STAT=1は境界ごとの当否を標準エラーへ
- 棄てた案: 境界ごとのパック（report-1194 5.1 — buildあたりの書きを1ファイルに減らせる）・頭に索引を置く形（値のまとまりを2回コピーする — 冷のRSS +28 MB）・関数ごとに作業のsliceを伸ばしながら外のsliceへ積む形（伸ばすたびに丸ごとコピーされる — 冷のRSS +770 MBの実発。相手の列はtable.Tableに）

## フェーズ3 R3 — staleのテスト

- **扉の監査**（`SOBER_CACHE_VERIFY=2` — bcache.soberのbcAud*・テスト = scripts/cacheaudit.sh）: 関数ごとの作り直し（α / β1 / β2）が鍵に入れた相手の外の事実を読まないことを、扉（lFnRet・xRegCc・x86の読み出し箇所xg）で記録して確認する。許しは鍵に入れた相手の記録の事実（ckFact — 関数の戻りの型とmut仮引数のフラグ・大域がワーカーの大域か）だけ。初回の監査で鍵の取りこぼし2つ（呼び先のmut仮引数のフラグ — x86の呼び出しの点が読む・罠の表の大域のフラグ）を特定し → 鍵へ（CK_VER 2）。xgの記録は木に書かず、テストが監査用のコンパイラにだけ差し込む（遅いパスは凍結の前のパスで熱く、分岐1つでoffの自己build +0.49 G）

- **incrbuild**（scripts/incrbuild.sh — --full）: 1つの格納場所に編集を積み重ねる自己buildの編集の連鎖（shift / dead / listat-sem / xfixadd-sem / panic-add / lambda-add / pure-flip〔spawnの子の純性〕/ addr-add / fnval〔関数を値に — 番地取り〕/ none）+ compiler-swap（出力の違うコンパイラで同じ格納場所 — 世代が分かれる）。基準は毎回W8・seed 0、温はW × seed × パス（相対 / 長い別パス + 絶対のentry）の8組を巡回（掛け算にしない）。progenのシード違いのprogramを1つの格納場所へ・例題 + bench（冷 / 温 / 検証）

## フェーズ3 R4 — 掃除と計測と文書

- **削除のAPI**: stdにunlink / rmdirが無かった → `std/os.Remove`（unlink — ディレクトリは消さない）・`std/os.RemoveDir`（空のディレクトリだけ）を足し（stdの生のsyscallの囲い — rtにもcompilerにもAPIを足さない）、compilerが使えるようブートストラップチェーンのステージ36に焼いた（report-1203 / 1204）。棄てた案: renameの上書きで消す（墓の名前へ順にrename — やっていることが書いてあることと違う・墓が残る）・os.Runで /bin/rm（distrolessで効かない）・消しを外の掃除に任せる（stage2を直に使う格納場所が溜まり続ける）
- **世代のLRUのマーク**: buildの終わりに世代のマーク `.used` をtmp + renameで置き直す（外れが0で書くパックが無いbuildもマークを置く）。LRUの時刻 = マークのmtime（時刻のAPIは要らない）。棄てた案: 世代のディレクトリのmtime（掃除が他の世代の一時ファイルを消すと進み、順位が狂う — R4-bのテストで実発）。`sober cache info` = 世代の一覧（新しい順・パック / 一時ファイルの数・大きさ・満杯）と上限（`SOBER_CACHE_GENS` 既定8・`SOBER_CACHE_MAX` MiB既定4096）
- **パックの名前 = `<pid>-<乱数>-<バイト数>.pack`**: 一覧（buildごとに走る）はReadDirだけで大きさを数える。棄てた案: io.Open + io.Stat（compilerの推移的な依存で初めて使うと自己buildの仕事 +2.15 G — 2×2で特定し・正体は未追跡）・毎回パックを読む（世代あたり28 MB）
- **buildの終わりの後始末（bcAfter）**: マーク → 満杯の記録 → 世代の中のゴミのしきい値 → 併合 → 根の掃除。錠は使わない — 消すのはrenameで隠してから（世代 → `.<世代>.dead-<pid>-<乱数>` にしてから中を名前で指定して消してrmdir）か、一覧の後に消えても読み手が外れとして扱うもの（パック — bcLoadは読めないパックを飛ばす）だけ。走っているbuildが読み込み中の世代が消えても外れになるだけで、書きは世代のディレクトリを作り直す
  - **併合**: 世代のパックが32本を超えたら、読めた全部を1本にまとめて書き（同じ鍵は先の方・検査和の合わない項目は捨てる・tmp + rename）元を消す。2本が同時に併合しても重複を持つパックが2本残るだけ（次の併合で畳まれる）
  - **世代の中のゴミのしきい値（設計提案1194 5.3 ③ からの変更 — report-1205・ナビ承認）**: 満杯 = 当たりが0のbuild（冷）が書いた大きさの最大（`.full`）・しきい値 = max(満杯 × 4, 下限64 MiB — `SOBER_CACHE_FLOOR`)。越えたら世代ごと捨てる（次は冷）。自己の世代では最初の冷28 MB × 4。棄てた案: 設計提案の「最初の満杯の4倍」（1つの世代を小さいプログラムが多数共有すると〔例題・stdの作業〕最初の1本の4倍をすぐ越えて捨て続ける）・作業集合の大きさ（当たりの値の長さをバッチの子から集める仕組みが要る）・格納場所全体の4 GBの上限だけ（bcLoadは世代の全部のパックを毎回読む — ゴミが読み込みの費用に比例して効く）
  - **根の掃除**: 隠した世代の残り（掃除の途中で止まった分）を消す・各世代の一時ファイルのうち10分より古いもの（書きの途中で死んだbuildの残り — 書きはbuildの終わりの一瞬なので、若い一時ファイルは走っている書き手のものとみなして残す）を消す・世代の数 > 上限か大きさの和 > 上限なら古い世代から捨てる（今の世代は捨てない）。年齢はファイルシステムの時計（今置いたマークのmtime）と比べる
  - `sober cache gc` = 同じ掃除を明示で（今のコンパイラの世代は捨てない）
- **テスト**（incrraceに足した分）: ③ 併合中の読み込み（パック33本の世代で併合するbuildと読むbuild 2本を同時に × 3 — ELF ≡ off・パックが1本に減る・併合の後の温が全部当たり・fsck緑）・④ 書きかけの一時ファイル（若いものは残し、古くした後は消える）・r6掃除（世代の数の上限・大きさの上限・ゴミのしきい値〔捨てた次は冷〕・隠した世代の残り・`cache gc`・build × gcの同時 × 4 — gcが読み込み中の世代を消してもELF ≡ off）
- **rebuildbenchの列**: whole（格納場所なし）・warm（編集前の木で温めた格納場所 — checkのC2 + フェーズ3）・alt（同じ格納場所を長い別パス + 絶対パスのentryでヒットさせる）・cold（空の格納場所）。外れ α/β1/β2・格納場所の大きさ・中央値の表。DIFFかNOCACHE（キャッシュのパスに入っていない）があれば落ちる
- **--fullの配置**: キャッシュのテスト4本はstagesの直後へ（後ろに置くと最後に長い札が重なる）・incrmutのミュータントは2本ずつ並べる（テストの強さはそのまま — 間引かない）・gatesの既定 -j 8・--fullの上限は10分（-j 6の詰めの下限 ≈657 s — ナビの決定）。棄てた案: テストを別タグにしてコミット直前に2段階（回す総量は同じでwallの和が増える）。次の改善 = selfparの中の段階の並列化（最長の札 — R4の外のピン）

## フェーズ2 — 番号の再配置化（札 + 後埋め + 安定な鍵）

**問題**: 機械語に焼かれる発見順の番号が3種類ある — panicの点の番号（`call rt.panic(const id)` のimm32）・spawnの点の番号（rt.task_newの第1引数 `site × 4 + 下 2 bit`）・ワーカーの表の番号（`mov r, fs:[8 × slot]` のdisp32）。どこか1か所で点が増えると後ろの番号が全部ずれ、自己buildで約60%の関数の機械語が変わっていた。加えてGVNが番号の定数を「値が同じ無関係な定数」と併合し、例題の一部（12本）でIRの形そのものが番号の値に依っていた。

**形**:
- **札**: 番号を運ぶ定数は `OpConst` のフィールドbに札（CT_PSITE / CT_SITE — lowerのiconstTag）を持つ。値は本物の番号のまま（IRテキストはaだけを印字 — stage1の照合・LLVMのパスは不変）。GVNの鍵は (op, a, b, c) なので札つきは札なしと併合されない
- **後埋め**: x86は札つきの定数のimm32を出す点（定数の定義・作り直し・storeの即値・並列の移し）でフィールドに0を書いて後埋め（種類3 = panicの点・4 = spawnの点）を追加し、ワーカーの表のdisp32は種類5にする。xModuleFrozenのpatchが番号を書く
- **安定な鍵**: 関数・番号を持ち主（下ろしていた関数）と持ち主の中の序数で引く材料をStのフィールドskに追加する（ヒープの外 — 関数の記録にフィールドを足すとヒープの番地がずれ、番地を含む名前〔specの複製 `$s<番地>`〕が動く）。鍵 = 関数・インスタンス・rtは名前・子の関数 `<持ち主>/K<序数>`・持ち上げたラムダ `<持ち主>/L<序数>`・specの複製 `<callee>$s(<位置>:<種類>:<値>;…)`・panic / spawnの点 `<持ち主>#p<序数>` / `#s<序数>`・大域は名前（文字列リテラルは中身のハッシュ）。ELF・irtext・symsの名前は変えない
- **成果物**: `sober build --emit=fnhash` = 関数ごとに 機械語（後埋めのフィールド = 0）‖ 後埋めの列（関数の頭からの位置・種類・相手の安定な鍵）のハッシュ

**テスト**: numpert（`SOBER_NUMOFF` で番号に下駄・`SOBER_NUMNOPATCH=1` で番号の後埋めを書かない → 下駄0 / 1 / 1000のELFがバイト一致。ミュータント3つ）・fnhash（`scripts/rebuildbench.sh --fnhash` — W1 ≡ W8・別パスのコピー・panic-add・lambda-addで、変わる関数 ⊆ 編集した関数とその下 + L類の合成rt。ミュータントで序数を全体で数えると自己の2,758関数がstray）。どちらもgates --fullだけ。

**棄てた案**:
- X（x86だけで番号の定数を形で認識して後埋め — 札なし）: 出力は完全に不変だが、GVNの併合で形が番号に依る関数を直せない（フェーズ3のキャッシュでstaleの穴）
- T'（札 + 値に下駄2^40を載せ、印字とx86で外す）: 後埋めの漏れがELFの一致で即鳴るが、値を読む全パスが下駄の値を見る危険を負う。札 + 摂動のテストで同じ強さが取れる
- C（番号を値として持たない新しいop）: 全パス・IRテキスト・stage1のIRパーサ・LLVMのパスにopを足す。費用が札の数倍で得は同じ

**パスごとの扱い**: 移植版のバックエンド（`--backend=copy`）は同じ出力の経路・同じ後埋めを通る（stage1とのバイト一致はelfeqが見る）。`--via=ll`（LLVMのパス）と `--via=stage1` はIRテキストを経るので番号は値のまま焼かれる — 開発用のパスでキャッシュの対象にしない（後埋めは要らない）。

## checkの関数単位キャッシュR3 — 脱糖の拒否の値と再生・watchの付け替え（report-1266）

- 脱糖の拒否（`desugar error at …`・NonExhaustive・ImmWriteなど — 位置つき）を帰す先のDefの値にする: タグCF_REJ ‖ 種類 ‖ kind ‖ 位置（R2と同じ項目の頭からの相対）‖ 2つ目の位置（NonExhaustiveのmissing — 型宣言の項目の中）。当たりなら脱糖せずに拒否を再生する（diag.WordsOf / FromWords）
- 帰す先 = 子の脱糖器が立てるS.rejDef（runのDefの回し — 関数i・根の本体nfn・前段と後回しの署名は −1）。持ち上げ（インスタンス・ラムダ）の本体の拒否は、それを最初に触ったDefの脱糖の中で起きるので、そのDefの「まっさらから脱糖すると拒否する」という値になる（鍵は使いの辺と本体の辺で持ち上げの本体を含む）
- 合流 = 逐次の再現: 逐次の脱糖はDefの順に進んで最初の拒否で止まり、検査より前に出る。子の拒否の区間では帰す先より前の外れは「脱糖は通った（検査はしていない — 書かない）」・後ろは不明。最初に拒否を持つDef（それより前が全部通ったと分かっている）の拒否を出す。Defの拒否が無ければ根の本体の拒否・帰す先の無い拒否（後回しの署名 — 署名の持ち主のDefが同じ拒否を持つはず）だけなら1本の経路へ。拒否のときも書ける値は書いてから返す
- watch: 小分けのcheck（checkSplitR）から一括のパス（checkFrontR — 既定の `sober check` と同じParCheck ‖ analyzer ‖ checkの並走）+ 境界Dへ。watchでは関数単位キャッシュを既定で使う（`SOBER_CHECK_CACHE=0` で切れる）。差分の出力（watchReport）は不変。小分けのcheckはL0の生成とpkgcheckの照合の役に残す。watchの下限（load + ParCheck + analyzerを毎周）はR4で扱う対象
- テスト: incrcheckの自己の編集の連鎖に脱糖の拒否の9ステップ（LenStringの拒否 → 前に字句を足して当たりの再生 → 直す・NonExhaustiveの2つ目の位置で同じ往復・共有インスタンスの本体の拒否 → 作り手の離脱 → 直す）と例題の3相目（checkverdictのゴールデンを当たりのまま — 拒否の再生）・incrmutのm20（当たりの拒否を再生しない）/ m21（2つ目の位置を値に書かない）・新ゲートwatchcheck（watchの6周の差分の出力をゴールデンと照合・最後の2周〔同じ拒否・同じ受理への戻り〕は全部当たり）
- 棄てた案: 拒否を位置の項目の持ち主のDefに帰す（インスタンスの本体の拒否はジェネリックの項目に落ちるが、逐次で拒否するのは最初に触ったDef）・子の拒否の区間の帰す先より前の外れも書く（検査をしていない）


## checkの関数単位キャッシュの既定on（watch温め係R1b — report-watch-1 7節）

- 既定をonに切り替えた（opt-out = `SOBER_CHECK_CACHE=0` — buildキャッシュの既定onと同じ形）。理由 = watchの温め係は問い合わせ側の素の `sober check` が格納場所を読むことを前提にする
- 冷onの正味: 自己checkのwall ±0（交互3周）・RSS +30 MB前後。小さい題材の +40 msは実行ファイル（16 MB）のハッシュ — 鍵を格納場所の `exekey-<kind>` に（大きさ, 更新時刻）で覚えるmemoで消した（buildの既定のパスも同じ分だけ速くなる）
- 計測とゴールデンのハーネス（gates・bench・stages・selfw）はbuildキャッシュと同じくoffのパスに固定（`SOBER_CHECK_CACHE=${SOBER_CHECK_CACHE:-0}`）。incrcheckのoffの基準は明示の `SOBER_CHECK_CACHE=0` に（envを外すと既定のonになる）
- テスト: incrcheckの例題の相にdefault（指定なしで冷 → 温 — 冷が格納場所に書くこと・温がゴールデンと一致すること）。offのパスはcheckverdict（格納場所なし）・stagesが見る
- 棄てた案: 問い合わせ側は答えの再生だけ既定onにして関数単位キャッシュはopt-inのまま（温め係が温めた領域を素のcheckが使えず、再生が外れた編集の直後に温めの得が消える）

## 答えの再生とwatchの温め（watch温め係R1a / R1c — report-watch-3 / 4）

- **答えの再生**: 既定の `sober check <entry>` の答え（終了コード・標準出力・診断）と既定の `sober build <entry>` のELFを格納場所（世代のディレクトリ）に丸ごと覚え、次の同じ問い合わせは計算せずに返す。鍵 = 種類 ‖ entryの綴り ‖ testのフラグ ‖ 答えに効く宣言済みの環境変数。値に読んだ利用者のファイルの中身のハッシュ（@embedの入力も）とそのディレクトリの .soberの名前の列のハッシュを持ち、引くときに全部照合する（編集・追加・削除で外れ）。`$layout/…` の合成のファイルは元のソースが決めるので外す
- **watchの温め**: 回の答えを素の `sober check` と同じ鍵で書く。受理の回の後はbuildを子プロセス（nice 19・ワーカーnproc / 4・flockで1本だけ）で切り離して起動し、待たない — 素の `sober build` が1回目から再生で当たる。編集の静止（SOBER_WATCH_QUIET — 既定200 ms）を待って回を始める
- コスト（このマシン）: 自己の `sober check app` 冷4.5 s → 再生0.05 s・`sober build app` 温4.7 s → 再生0.27 s（ELF 12 MBの読み込みと照合と書き）・例題のcheck 10 ms未満
- テスト: watchcheck（問い合わせの相 — watchの後の当たり・編集 / 追加 / 環境変数で外れ・buildの再生とwatchの温めの後の初回の当たり・ELFの一致）・incrcheckの例題のdefault相。関数単位キャッシュのテストはSOBER_CHECK_REPLAY=0で再生を切る
- 棄てた案: 再生の鍵に推移的な依存のファイルの中身を入れる（引く前に推移的な依存を知るにはloadが要り、瞬時にならない — 値に一覧を持って照合する入力の発見型にした）・watchのbuildを待つ（回がbuildの分だけ遅れ、診断の差分が遅れる）
## テストの結果の再生（検証の四点セットT1 — report-test-2）

- コスト（このマシン）: compiler/ のlexer等の当たり4〜15 ms（外れのbuild + 実行0.2〜0.8 s）。テストのビルドはbuildと同じ後段の関数キャッシュのパス（lowerの `sober test` 5.7 → 3.8 s）
