## 段 3 R2 — 置き場と α・β（lower/bcache.sober）

- **置き場**: `<cacheDir>/sober-build-1/<コンパイラの鍵の先頭 16 桁>/`（鍵 = bin/sober の SOBER_SELF_KEY か、実行ファイルの語単位の混ぜ 2 本 — SHA-256 は 10 MB で約 0.8 G 命令）。build ごとに外れた値を 1 つのパック `<pid>-<uuid>.pack` に（tmp + rename・不変）。パック = 値の並び + 索引（varint の [切り口, 鍵 h1, h2, 位置, 長さ, 値の検査和]）+ 尾 24 B（印・索引の長さ・索引の検査和）。読みは世代の全パックの索引を表にし、当たりの値を検査和で確かめてから使う
- **α**（鍵 = B1 の入力）: 値 = B1 の後の本体の詰めた形（mvPack）の正準形 — 外を指す語（K_FN / K_GLOB・札つきの定数）だけ安定な鍵のハッシュへ。W1 は本体を壊さずにヒープから直に同じバイト列を作る（bcAlphaHeap — 検証モードで詰める道と照合）・W ≥ 2 は束の子が詰めた形に相乗り。当たりは読み戻して mvUnpack（束の子の結果と同じ道）
- **β1**（鍵 = B2 の入力）: 値 = B2 の後の呼び出し / 番地取りの相手の列。当たりの関数は B2 を飛ばし（本体は入力のまま）、cutInsert の到達性と番地取りの印をこの列で組む。切替 / 罠を持つ関数は書かない（毎回）
- **β2**（鍵 = ckBeta）: 値 = 機械語（吐き始め〔整列の後〕から出した長さまで — 入口は線の跨ぎの詰め物の分だけ後ろでありうるので入口の位置も持つ）+ 後埋めの列（安定な鍵）+ xmm の組。機械語は後埋めの後の ELF から切り出して後埋めの欄を 0 に戻す。β1 が当たって β2 が外れた関数は、x86 の凍結の前に B2 と検査点を遅れて掛けて検証する
- **検証モード**（SOBER_CACHE_VERIFY=1）: 何も飛ばさずに作り、置き場に同じ鍵があればバイトで比べる（違えば `cache: stale entry <切り口> <鍵>` で落ちる）。SOBER_CACHE_STAT=1 は切り口ごとの当否を標準エラーへ
- 棄てた案: 切り口ごとのパック（report-1194 5.1 — build あたりの書きを 1 ファイルに減らせる）・頭に索引を置く形（値の束を 2 回写す — 冷の RSS +28 MB）・関数ごとに作業の slice を伸ばしながら外の slice へ積む形（伸ばすたびに丸ごと写る — 冷の RSS +770 MB の実発。相手の列は table.Table に）

## 段 3 R4 — 掃除と計測と文書

- **消しの口**: std に unlink / rmdir が無かった → `std/os.Remove`（unlink — ディレクトリは消さない）・`std/os.RemoveDir`（空のディレクトリだけ）を足し（std の生の syscall の囲い — rt にも compiler にも口を足さない）、compiler が使えるよう鎖の段 36 に焼いた（report-1203 / 1204）。棄てた案: rename の上書きで消す（墓の名前へ順に rename — やっていることが書いてあることと違う・墓が残る）・os.Run で /bin/rm（distroless で効かない）・消しを外の掃除に任せる（stage2 を直に使う置き場が溜まり続ける）
- **世代の LRU の印**: build の終わりに世代の印 `.used` を tmp + rename で置き直す（外れが 0 で書くパックが無い build も印を置く）。LRU の時刻 = 印の mtime（時刻の API は要らない）。棄てた案: 世代のディレクトリの mtime（掃除が他の世代の一時ファイルを消すと進み、順位が狂う — R4-b の網で実発）。`sober cache info` = 世代の一覧（新しい順・パック / 一時ファイルの数・大きさ・満杯）と線（`SOBER_CACHE_GENS` 既定 8・`SOBER_CACHE_MAX` MiB 既定 4096）
- **パックの名前 = `<pid>-<乱数>-<バイト数>.pack`**: 一覧（build ごとに走る）は ReadDir だけで大きさを数える。棄てた案: io.Open + io.Stat（compiler の閉包で初めて使うと自己 build の仕事 +2.15 G — 2×2 で名指し・正体は未追跡）・毎回パックを読む（世代あたり 28 MB）
- **build の終わりの後始末（bcAfter）**: 印 → 満杯の記録 → 世代の中のゴミの線 → 併合 → 根の掃除。錠は使わない — 消すのは rename で隠してから（世代 → `.<世代>.dead-<pid>-<乱数>` にしてから中を名指しで消して rmdir）か、一覧の後に消えても読み手が外れとして扱うもの（パック — bcLoad は読めないパックを飛ばす）だけ。走っている build の読みかけの世代が消えても外れになるだけで、書きは世代のディレクトリを作り直す
  - **併合**: 世代のパックが 32 本を超えたら、読めた全部を 1 本にまとめて書き（同じ鍵は先の方・検査和の合わない項目は捨てる・tmp + rename）元を消す。2 本が同時に併合しても重複を持つパックが 2 本残るだけ（次の併合で畳まれる）
  - **世代の中のゴミの線（起案 1194 5.3 ③ からの変更 — report-1205・ナビ承認）**: 満杯 = 当たりが 0 の build（冷）が書いた大きさの最大（`.full`）・線 = max(満杯 × 4, 床 64 MiB — `SOBER_CACHE_FLOOR`)。越えたら世代ごと捨てる（次は冷）。自己の世代では最初の冷 28 MB × 4。棄てた案: 起案の「最初の満杯の 4 倍」（1 つの世代を小さいプログラムが多数共有すると〔例題・std の作業〕最初の 1 本の 4 倍をすぐ越えて捨て続ける）・作業集合の大きさ（当たりの値の長さを束の子から集める道が要る）・置き場全体の 4 GB の線だけ（bcLoad は世代の全部のパックを毎回読む — ゴミが読みの費用に比例して効く）
  - **根の掃除**: 隠した世代の残り（掃除の途中で止まった分）を消す・各世代の一時ファイルのうち 10 分より古いもの（書きの途中で死んだ build の残り — 書きは build の終わりの一瞬なので、若い一時ファイルは走っている書き手のものとみなして残す）を消す・世代の数 > 上限か大きさの和 > 線なら古い世代から捨てる（今の世代は捨てない）。年齢はファイルシステムの時計（今置いた印の mtime）と比べる
  - `sober cache gc` = 同じ掃除を明示で（今のコンパイラの世代は捨てない）
- **網**（incrrace に足した分）: ③ 併合中の読み（パック 33 本の世代で併合する build と読む build 2 本を同時に × 3 — ELF ≡ off・パックが 1 本に減る・併合の後の温が全部当たり・fsck 緑）・④ 書きかけの一時ファイル（若いものは残し、古くした後は消える）・r6 掃除（世代の数の線・大きさの線・ゴミの線〔捨てた次は冷〕・隠した世代の残り・`cache gc`・build × gc の同時 × 4 — gc が読みかけの世代を消しても ELF ≡ off）
- **rebuildbench の列**: whole（置き場なし）・warm（編集前の木で温めた置き場 — check の C2 + 段 3）・alt（同じ置き場を長い別パス + 絶対パスの entry で当てる）・cold（空の置き場）。外れ α/β1/β2・置き場の大きさ・中央値の表。DIFF か NOCACHE（キャッシュの道に入っていない）があれば落ちる
- **--full の置き場**: キャッシュの網 4 本は stages の直後へ（後ろに置くと最後に長い札が重なる）・incrmut のミュータントは 2 本ずつ並べる（テストの強さはそのまま — 間引かない）・gates の既定 -j 8・--full の線は 10 分（-j 6 の詰めの下限 ≈657 s — ナビ裁定）。棄てた案: 網を別タグにしてコミット直前に 2 段（回す総量は同じで wall の和が増える）。次の改善 = selfpar の中の段の並列化（最長の札 — R4 の外のピン）

## 段 2 — 番号の再配置化（札 + 後埋め + 安定な鍵）

**問題**: 機械語に焼かれる発見順の番号が 3 種類ある — panic の点の番号（`call rt.panic(const id)` の imm32）・spawn の点の番号（rt.task_new の第 1 引数 `site × 4 + 下 2 bit`）・ワーカーの表の番号（`mov r, fs:[8 × slot]` の disp32）。どこか 1 か所で点が増えると後ろの番号が全部ずれ、自己 build で約 60% の関数の機械語が変わっていた。加えて GVN が番号の定数を「値が同じ無関係な定数」と併合し、例題の一部（12 本）で IR の形そのものが番号の値に依っていた。

**形**:
- **札**: 番号を運ぶ定数は `OpConst` の欄 b に札（CT_PSITE / CT_SITE — lower の iconstTag）を持つ。値は本物の番号のまま（IR テキストは a だけを印字 — stage1 の照合・LLVM の道は不変）。GVN の鍵は (op, a, b, c) なので札つきは札なしと併合されない
- **後埋め**: x86 は札つきの定数の imm32 を出す点（定数の定義・作り直し・store の即値・並列の移し）で欄に 0 を書いて後埋め（種類 3 = panic の点・4 = spawn の点）を積み、ワーカーの表の disp32 は種類 5 にする。xModuleFrozen の patch が番号を書く
- **安定な鍵**: 関数・番号を持ち主（下ろしていた関数）と持ち主の中の序数で引く材料を St の欄 sk に積む（ヒープの外 — 関数の記録に欄を足すとヒープの番地がずれ、番地を含む名前〔spec の複製 `$s<番地>`〕が動く）。鍵 = 関数・インスタンス・rt は名前・子の関数 `<持ち主>/K<序数>`・持ち上げたラムダ `<持ち主>/L<序数>`・spec の複製 `<callee>$s(<位置>:<種類>:<値>;…)`・panic / spawn の点 `<持ち主>#p<序数>` / `#s<序数>`・大域は名前（文字列リテラルは中身のハッシュ）。ELF・irtext・syms の名前は変えない
- **成果物**: `sober build --emit=fnhash` = 関数ごとに 機械語（後埋めの欄 = 0）‖ 後埋めの列（関数の頭からの位置・種類・相手の安定な鍵）のハッシュ

**網**: numpert（`SOBER_NUMOFF` で番号に下駄・`SOBER_NUMNOPATCH=1` で番号の後埋めを書かない → 下駄 0 / 1 / 1000 の ELF がバイト一致。ミュータント 3 つ）・fnhash（`scripts/rebuildbench.sh --fnhash` — W1 ≡ W8・別パスの写し・panic-add・lambda-add で、変わる関数 ⊆ 編集した関数とその下 + L 類の合成 rt。ミュータントで序数を全体で数えると自己の 2,758 関数が stray）。どちらも gates --full だけ。

**棄てた案**:
- X（x86 だけで番号の定数を形で認識して後埋め — 札なし）: 出力は完全に不変だが、GVN の併合で形が番号に依る関数を直せない（段 3 のキャッシュで stale の穴）
- T'（札 + 値に下駄 2^40 を載せ、印字と x86 で外す）: 後埋めの漏れが ELF の一致で即鳴るが、値を読む全パスが下駄の値を見る危険を負う。札 + 摂動の網で同じ強さが取れる
- C（番号を値として持たない新しい op）: 全パス・IR テキスト・stage1 の IR パーサ・LLVM の道に op を足す。費用が札の数倍で得は同じ

**道ごとの扱い**: 写しのバックエンド（`--backend=copy`）は同じ出し口・同じ後埋めを通る（stage1 とのバイト一致は elfeq が見る）。`--via=ll`（LLVM の道）と `--via=stage1` は IR テキストを経るので番号は値のまま焼かれる — 開発の道でキャッシュの対象にしない（後埋めは要らない）。

## check の関数単位キャッシュ R2 — 置き場と飛ばし（checker/defcache.sober・desugar/defcache.sober — report-1263）

- **使う持ち上げ**: 共有の持ち上げ（インスタンス・辞書 const のラムダ）は子の中で最初に触った Def が作る。作った Def に帰すと、作り手が外れて使い手だけ当たる編集で落ちを見落とす（incrcheck の inst-drop）。脱糖器が使いの辺（文脈 → 持ち上げ — 作るときと memo の当たり。インスタンスの本体の中は文脈を切り替え・ラムダは本体の後に添字が決まるので待ちの文脈）を積み、子が「Def から届く持ち上げの最初の落ち」を Def の値にする。どの文脈からも届かない落ちは 1 本の経路へ落とす
- 合流（逐次の checkAll の順）: 最初に名前付きの落ちを持つ関数 → 無ければ最初に持ち上げの落ちを持つ関数 → 根の持ち上げ → 根の判定。脱糖の拒否・帰す先の無い落ちは 1 本の経路で走らせ直して何も書かない（拒否の値は R3）・深すぎた子の外れは書かない
- 網: `scripts/incrcheck.sh`（自己の鎖 22 段 — 位置だけ・本体・署名・const・型・拒否の往復と位置の付け直し・ラムダの落ち・共有インスタンスの作り手の離脱・展開される関数の本体の誤り・呼び先の署名で呼び手が落ちる。温は W{1,8} × パス {本来, 長い別パス}・base は =2・3 段は =1。続けて checkverdict の黄金 846 本を冷 → 温 =1）・incrmut の m15 / m17 / m18 / m19（使いの辺・展開の本体の辺・位置の相対・参照の辺を 1 つずつ落とす）
- 棄てた案: 位置を絶対の字句で持つ（前に字句を足す編集で古い位置 — m18）・持ち上げの落ちを作った Def だけに帰す（m15 の形）・拒否の値も R2 で書く（R3 の席）・ジェネリックの本体の辺 ② を網で確かめるミュータント（m16 — インスタンス化の呼び出しには辺 ④ が必ず同じ本体へ張られる同値のミュータント）

## check の関数単位キャッシュ R3 — 脱糖の拒否の値と再生・watch の付け替え（report-1266）

- 脱糖の拒否（`desugar error at …`・NonExhaustive・ImmWrite など — 位置つき）を帰す先の Def の値にする: 印 CF_REJ ‖ 種類 ‖ kind ‖ 位置（R2 と同じ項目の頭からの相対）‖ 2 つ目の位置（NonExhaustive の missing — 型宣言の項目の中）。当たりなら脱糖せずに拒否を再生する（diag.WordsOf / FromWords）
- 帰す先 = 子の脱糖器が立てる S.rejDef（run の Def の回し — 関数 i・根の本体 nfn・前段と後回しの署名は −1）。持ち上げ（インスタンス・ラムダ）の本体の拒否は、それを最初に触った Def の脱糖の中で起きるので、その Def の「まっさらから脱糖すると拒否する」という値になる（鍵は使いの辺と本体の辺で持ち上げの本体を含む）
- 合流 = 逐次の再現: 逐次の脱糖は Def の順に進んで最初の拒否で止まり、検査より前に出る。子の拒否の区間では帰す先より前の外れは「脱糖は通った（検査はしていない — 書かない）」・後ろは不明。最初に拒否を持つ Def（それより前が全部通ったと分かっている）の拒否を出す。Def の拒否が無ければ根の本体の拒否・帰す先の無い拒否（後回しの署名 — 署名の持ち主の Def が同じ拒否を持つはず）だけなら 1 本の経路へ。拒否のときも書ける値は書いてから返す
- watch: 小分けの check（checkSplitR）から一括の道（checkFrontR — 既定の `sober check` と同じ ParCheck ‖ analyzer ‖ check の並走）+ 切り口 D へ。watch では関数単位キャッシュを既定で使う（`SOBER_CHECK_CACHE=0` で切れる）。差分の出力（watchReport）は不変。小分けの check は L0 の生成と pkgcheck の照合の役に残す。watch の床（load + ParCheck + analyzer を毎周）は R4 の席
- 網: incrcheck の自己の鎖に脱糖の拒否の 9 段（LenString の拒否 → 前に字句を足して当たりの再生 → 直す・NonExhaustive の 2 つ目の位置で同じ往復・共有インスタンスの本体の拒否 → 作り手の離脱 → 直す）と例題の 3 相目（checkverdict の黄金を当たりのまま — 拒否の再生）・incrmut の m20（当たりの拒否を再生しない）/ m21（2 つ目の位置を値に書かない）・新ゲート watchcheck（watch の 6 周の差分の出力を黄金と照合・最後の 2 周〔同じ拒否・同じ受理への戻り〕は全部当たり）
- 棄てた案: 拒否を位置の項目の持ち主の Def に帰す（インスタンスの本体の拒否はジェネリックの項目に落ちるが、逐次で拒否するのは最初に触った Def）・子の拒否の区間の帰す先より前の外れも書く（検査をしていない）


## check の関数単位キャッシュの既定 on（watch 温め係 R1b — report-watch-1 7 節）

- 既定を on に倒した（opt-out = `SOBER_CHECK_CACHE=0` — build キャッシュの既定 on と同じ形）。理由 = watch の温め係は問い合わせ側の素の `sober check` が置き場を読むことを前提にする
- 冷 on の正味: 自己 check の wall ±0（交互 3 周）・RSS +30 MB 前後。小さい題材の +40 ms は実行ファイル（16 MB）のハッシュ — 鍵を置き場の `exekey-<kind>` に（大きさ, 更新時刻）で覚える memo で消した（build の既定の道も同じ分だけ速くなる）
- 計測と黄金のハーネス（gates・bench・stages・selfw）は build キャッシュと同じく切の道に固定（`SOBER_CHECK_CACHE=${SOBER_CHECK_CACHE:-0}`）。incrcheck の off の基準は明示の `SOBER_CHECK_CACHE=0` に（env を外すと既定の on になる）
- 網: incrcheck の例題の相に default（指定なしで冷 → 温 — 冷が置き場に書くこと・温が黄金と一致すること）。off の道は checkverdict（置き場なし）・stages が見る
- 棄てた案: 問い合わせ側は答えの再生だけ既定 on にして関数単位キャッシュは opt-in のまま（温め係が温めた区画を素の check が使えず、再生が外れた編集の直後に温めの得が消える）

## 答えの再生と watch の温め（watch 温め係 R1a / R1c — report-watch-3 / 4）

- **答えの再生**: 既定の `sober check <entry>` の答え（終了コード・標準出力・診断）と既定の `sober build <entry>` の ELF を置き場（世代のディレクトリ）に丸ごと覚え、次の同じ問い合わせは計算せずに返す。鍵 = 種類 ‖ entry の綴り ‖ test の印 ‖ 答えに効く宣言済みの環境変数。値に読んだ利用者のファイルの中身のハッシュ（@embed の入力も）とそのディレクトリの .sober の名前の列のハッシュを持ち、引くときに全部照合する（編集・追加・削除で外れ）。`$layout/…` の合成のファイルは元のソースが決めるので外す
- **watch の温め**: 回の答えを素の `sober check` と同じ鍵で書く。受理の回の後は build を子プロセス（nice 19・ワーカー nproc / 4・flock で 1 本だけ）で切り離して起こし、待たない — 素の `sober build` が 1 回目から再生で当たる。編集の静止（SOBER_WATCH_QUIET — 既定 200 ms）を待って回を始める
- 値札（この箱）: 自己の `sober check app` 冷 4.5 s → 再生 0.05 s・`sober build app` 温 4.7 s → 再生 0.27 s（ELF 12 MB の読みと照合と書き）・例題の check 10 ms 未満
- 網: watchcheck（問い合わせの相 — watch の後の当たり・編集 / 追加 / 環境変数で外れ・build の再生と watch の温めの後の初回の当たり・ELF の一致）・incrcheck の例題の default 相。関数単位キャッシュの網は SOBER_CHECK_REPLAY=0 で再生を切る
- 棄てた案: 再生の鍵に閉包のファイルの中身を入れる（引く前に閉包を知るには load が要り、瞬時にならない — 値に一覧を持って照合する入力の発見型にした）・watch の build を待つ（回が build の分だけ遅れ、診断の差分が遅れる）
## テストの結果の再生（検証の四点セット T1 — report-test-2）

- **形**: `sober test` の package ごとに、全部通ったときの印字（書き出した順の標準出力 / 標準エラーの列 — 子の出力は std/os.RunTo で捕まえる）を置き場（build の世代のディレクトリ）に覚え、次の同じ問い合わせは建てずに走らせずに返す。鍵 = package の綴り ‖ --run の接頭辞 ‖ PWD ‖ 環境の SOBER_* の全部（rt が読むシード・ワーカー数等 — 宣言の表に無いものも。置き場・計測・watch の口は除く）。値 = 答えの再生と同じ読んだファイル・ディレクトリの照合 + package の testdata/ の丸ごと（相対の名前と中身 — 再帰）+ テストのコードが読む環境変数の値
- **読む環境変数は静的に集める**: 利用者のファイルの木から `os.Getenv("名前")` のリテラルと std/env・std/cli の表の行（`…StrVar` / `IntVar` / `BoolVar` / `…Env` の `name:`）。リテラルでない読みが 1 つでもあれば覚えない（何を読むか分からない — fail-closed）。std の package のテストは利用者のファイルが無い（焼き込み）ので覚えない
- **覚えないもの**: 失敗のある package（失敗はいつも走らせ直す）。`--fresh` は引かずに走らせ直す（覚え直す）。切る口 = SOBER_CHECK_REPLAY=0（gates の既定 — 網は実際の走りを見る）。SOBER_CACHE_VERIFY=1/2 は当たりも走らせて印字の一致を照合する（不一致は InvariantBroken）
- **穴（承知の上）**: テストが PWD の外・testdata の外のファイルを相対 / 絶対パスで読む・子プロセスの環境を介して読む・時計やネットワークに依る — 当たりは前の印字を返す。io の読みの記録（実行時に読んだファイルと環境変数を rt が書き出す）は後便
- **watch の温めの列**: 受理の回の後、L1 = build → L2 = 見張りの閉包のディレクトリのうち *_test.sober を持つ package の `sober test` を 1 本の列（setsid のプロセスグループ — nice 19・build のワーカーは nproc / 4・テストは絞らない〔SOBER_WORKERS は鍵〕）として切り離して起こし、待たない。テストのビルドは build と同じ後段の関数キャッシュを引くので直列が速い。次の回の頭で前の列を止め（SIGTERM をグループへ — 途中で止めた書きは tmp + rename で原子的）、受理なら最新を温め直す（以前の flock -n は温めの最中の編集の後の受理を飛ばし、最後の編集が温まらない窓があった）。列は `<置き場>/watch/<id>.pid` に自分の pid・`<id>.warm` に進み（`start <pid>`・`build <終了コード>`・`test <終了コード>`・`done <pid>`）を書く（id = PWD ‖ entry のハッシュの先頭 16 桁）。切る口 = SOBER_WATCH_BUILD=0 / SOBER_WATCH_TEST=0（層ごと）。前景との協調は nice のまま（実測 — 自己 check の外れ 0.37 s が nice 19 の build ×3 の裏で 0.37〜0.44 s・コア 4〜8 の箱は未測定 — 足すときの網は前景 wall の比）
- **状態ファイル**: watch が唯一の書き手で、`<置き場>/watch/<id>.json` を状態が変わるたびに tmp + rename で書き直す — `{"version":1,"pid":…,"cwd":"…","entry":"…","round":…,"phase":"checking|idle","verdict":"none|ok|rejected","diags":["…"],"warm":{"build":"…","test":"…"}}`。diags は標準エラーへ出す診断の行と同じ文字列（欄に分けた構造化は開発用の前段〔dev プロキシ〕の便で）。warm = off / none / skipped / queued / running / done / failed / stopped（列の進み `<id>.warm` をポーリングの周で写す）。`sober cache info` が 1 行ずつ出す（pid が生きていなければ (stale)）
- 値札（この箱）: compiler/ の lexer 等の当たり 4〜15 ms（外れの build + 実行 0.2〜0.8 s）。テストのビルドは build と同じ後段の関数キャッシュの道（lower の `sober test` 5.7 → 3.8 s）
- 網: testreplay（問い合わせの相 33 本 — 状態ファイルの遷移〔受理 → 拒否 → 直す〕と cache info の行・stale を含む — watch の温めの後の初回の当たり・温めの最中の編集で最新が温まる・長い列が編集で数秒の内に止まる〔build の ELF とテストの印字は置き場なしと一致〕を含む — 当たり・ソースの編集 / .sober の追加 / testdata の編集と追加 / 読む環境変数 / SOBER_* / --run / --fresh で外れ・失敗とリテラルでない読みは覚えない・印字は置き場なしとバイト一致）。照合を落とすミュータント 3 本（ファイルの中身・testdata・環境変数の値）を名指しすることを確かめた
- 棄てた案: 鍵に宣言済みの環境変数（Sober.env）だけを入れる（テストは宣言されていない環境変数を読む — DEFLATE_BENCH 等の実例・rt の SOBER_WORKERS 等も表に無い）・環境の全部を鍵に（端末の揺れで外れ続ける）・失敗も覚える（揺れる失敗が焼き付く）
## check の関数単位キャッシュ R4 — 前段の流用（P0・analyzer の γ・鍵の組み立て — report-1267 / report-1268）

- 偵察（report-1267）: 区間の子の前段の TypeAll は部分の型付け（rangeReach — 届く関数だけ）で区画が全部の型付けと違うので γ は効かない（TypeAllC が意図して切る）→ ナビ裁定 = 案 A: ① P0 を check の道へ ② 鍵の組み立て（dkGraph）を軽く ③ analyzer の全部の型付けに γ を読む
